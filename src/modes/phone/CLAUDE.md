# スマホ版（無料・腰に付けて外を走る）

仕様は `docs/phone-spec.md`（ユーザーと決めた）。材料は `docs/research/phone-methods.md`・`docs/research/phone-competitors.md`。

## 目的

スマホを腰（ウエストポーチ・ランニングベルト）に付けて外を走り、加速度・ジャイロで走りを測って、走っている最中に直す。アプリの売り（その場の声かけ）を無料で体験してもらう入口。
姿勢はほとんど見えず、腰のスマホで測る研究もないので、外れた声をかけないことを何より優先する。声で直すのはピッチ1つに絞る。

## 範囲

- このフォルダ（見る役・付け方の確認・項目・線・模擬データ）と、スマホの入り口の画面、iPhone アプリ化の設定、`phrases.ts` への言葉の追加
- 声かけのしくみ（`src/core/engine.ts`）としくみの数字は共通のもの。スマホ版の都合で直したいときは、カメラ版を壊さない形で直す

## いまの状態

- 見る役：ピッチ・上下動・着地のブレーキ。模擬データでは合っているが、模擬データ自体が同じ仮定で作られているので、本当の精度は分からない
- ブレーキの向き：ジャイロがあれば、1コマごとの向きの変わりを積み重ねて加速度を窓の始まりの向きにそろえてから前後の加速度を積分する（`signal.ts` の `levelled`）。骨盤の前後の傾きで重力が前後に漏れ込むのを防ぐため。ジャイロのずれは、窓の平均の角速度のうち上下の軸に直交する分を引いて減らす。ジャイロがない端末では数歩の平均の向きで固定（前の方法）。前の方法の値も `brakingFixed` として記録に残す。模擬データ（骨盤が1歩ごとに前後に5°傾く走り、入れたブレーキ 0.3 m/s）で、固定すると 0.23〜0.39、直すと 0.31〜0.32
- 疲れの見分け（声なし）：`fatigue.ts`。1秒ごとに、上下と前後の1歩ずらした自己相関・3方向の揺れの割合・有効接地時間（上下の加速度が1gを上回る時間）を出し、走り終わった後に、基準の区間（5〜12分。足りなければ30秒〜3分）と比べた「いつもと違う度合い」を1分ごとに出す。線を超えた区間が続いた始まりが崩れ始め（`session.breakdownMin` もここから）。速さで止めた秒・付け方の問題が見つかった後の秒は使わない。数字（`FATIGUE`）はどれも根拠のない仮の値
- 付け方の確認（`mount.ts`）：腰以外（腕・手・ポケット）・ゆるい・途中でずれた、を見分けて1回だけ知らせ、その走りでは判定を止めて記録に印。主な手がかりはジャイロ。線（`MOUNT`）は模擬データだけで決めた仮の値
- 線（`PHONE_LIMITS`）は、ピッチの5%（Heiderscheit 2011）以外は根拠のない仮の値
- 角速度は rad/s で受け取る。Web の DeviceMotion の rotationRate は deg/s なので、`sensor.ts` の `toMeasure` で直す（alpha→z、beta→x、gamma→y）。加速度は accelerationIncludingGravity をそのまま渡す（3つの軸の符号がそろって逆の機種でも、見る役の値は変わらない）
- 画面（ウェブ）：ホームのスマホ版の欄で、上の「どこで走る？」（外 / トレッドミル。端末に覚える：`storage.ts` の `loadPhoneWhere`）を選び、下の同じ形の3つのボタン（「走る」「ピッチを上げる練習」「フォームのテスト」）のどれかを押すと、選んだ場所で始まる（`Home.tsx` の `startPhone(where, kind)`）。押したときに動きのセンサーの許可と画面が消えない仕組み（Wake Lock）を求め、`screens/PhoneLive.tsx` で測って声をかける。結果は `screens/PhoneResult.tsx`（カメラ版の結果とは別）。いつもと違う度合いと崩れ始め、上下動・ブレーキ・有効接地時間の走り始めからの変化を1分ごとのグラフで出す（良し悪しは言わない）。1回の走りの中身は画面から切り離した `session.ts` の `PhoneRun`。声にする項目はピッチだけ（`PHONE_VOICED`）。ブレーキ・上下動は、大きく崩れても声をかけない（しくみの `muteOthers`）。付け方の確認の声は別にかかる
- 記録：`log.ts`。生の値（届いたコマすべて：t・ふつうの時刻 wallMs・加速度・角速度・しくみの状態）と1秒ごとの判定の値（測った値・線と比べた値・付け方の手がかり・疲れの見分けの材料）と疲れの見分けの結果（`fatigue`）を残し、`storage.ts` の `exportPhoneLog` でカメラ版と同じ形（`{ log, session }`）に書き出す。列の意味はファイルの `units` に入る。送る鍵を入れた端末では、走り終わると同じ中身を Mac へ送る（`core/upload/`、`npm run logs`）
- カメラ版と比べる道具：`compare.ts`（`npm run compare -- <スマホ版の書き出し> <カメラ版の書き出し>`、`scripts/compare-runs.mjs`）。2つの記録をふつうの時刻に直し、動きの強さ（加速度・腰の高さの揺れ）の相関で2台の時計のずれを直して、区間ごとにピッチ・上下動・ブレーキ・付け方の確認を並べる。カメラ版の記録には、performance.now() とふつうの時刻の対応（`clock`）が入る。手順は `docs/phone-test1.md`。確かめたのは模擬データだけ
- ピッチの知らせ：言葉は初めの1回だけで、あとは基準のテンポのメトロノーム（`core/metronome.ts`、Web Audio の時刻で拍を予約）を最大 `TONE.bars` 小節。戻ったら止め、くり返すほど間をあける（`TONE`）。しくみの `ItemSpec.tone` と `tone` の知らせで出し、カメラ版の項目には付けていない。声の間は拍を鳴らさない
- 基準：仮の基準（30秒〜3分）で判定を始め、5〜12分の平均ができたら置き換える（`PHONE_REF`。仮の基準から5%より下がった秒は入れない）。メトロノームのテンポも新しい基準になる
- 音の種類は `playback`（消音スイッチがオンでも鳴る代わりに、ほかのアプリの音楽を止める見込み）。実機テスト②（`docs/phone-test2.md`）で確かめて決める
- 速さで判定を止める（`speed.ts`、数字は `SPEED`）：外（`PhoneRun` の `where: 'outdoor'`）では位置情報（Geolocation）の速さをならし、基準の速さ（ピッチの基準と同じ区間で取る）から ±10% 外れた秒・GPS が取れない秒は判定しない。止めた秒は新しく知らせず、メトロノームも止める（しくみの `holdUnjudged`）。理由は記録の `gate` 列と `gate:on:理由` の出来事に残る。±10% は根拠のない仮の値。坂はウェブでは見ない（気圧計がなく、GPS の高さでは見分けられない。高さは記録にだけ残す）
- 外とトレッドミル：ホームの「どこで走る？」で外を選ぶと、押したときに動きのセンサー・位置情報の許可をまとめて求める。トレッドミルを選ぶと GPS を使わず、速さは一定とみなす。どちらでも3つのボタンは同じ。日常で使わないもの（直近の記録を書き出す・模擬データで試す・送る鍵）は、欄の下の閉じた「開発用」に入れている。「模擬データで試す」はトレッドミル扱い
- ピッチを上げる練習（`practice.ts`、数字は `PRACTICE`）：ホームの「ピッチを上げる練習」（外でもトレッドミルでも）。`PhoneRun` に種類（`PhoneKind`）を渡すと、しくみではどの項目も知らせず（ピッチが落ちたときのメトロノームは鳴らない）、練習のテンポのメトロノームだけを `tone`（item は `practice`、止めるまで鳴らす）で出す。何回目か・自分のピッチは保存した走り（`PhoneSession.practice`）から数える。結果は `screens/PhoneProgress.tsx`
- フォームのテスト（`formtest.ts`、数字は `FORM_TEST`）：ホームの「フォームのテスト」。声はかけず5分で終える。始めの1分を除いた平均を `PhoneSession.test` に残し、前のテストと比べ、速さ（GPS）がそろっていなければそう言う
- 崩しの撮影（`drill.ts`）：ホームで「トレッドミル」を選んだときだけ出る「崩しの撮影（声で指示）」。ふつう版・短い版と、最後に付け方の区間（ゆるい・手・ポケット）を走るかを選ぶ。準備30秒 → ベルトを止めたままジャンプ3回 → 10秒立つ → ベルトを動かす → 区間（ふつう・頭を前に・猫背・体ごと前に・腰を落とす・ピッチを落とす・弾む・かかとから前に・べた足・ふつう〔・ゆるい・手に持つ・ポケット〕）。区間のあいだは15秒（付け方を変える前は30秒）ふちに立って休む → ジャンプ3回で終わる。区間の前に名前とやり方、始まりに合図、残り10秒で予告、終わりに「休みます」を言う。区間の始まりと終わりは記録の events に `protocol:<key>:start` / `end`（ジャンプと立つ間は jump1・still・jump2、やめたら `protocol:stopped`、最後まで進んだら `protocol:done`）。key は `compare.ts` の区間の名前（`DRILL`。TEST1 と同じものは同じ key）で、`compare.ts` は印があれば休みの見分けより先にそれで区間を決める。ピッチの声・メトロノーム・付け方の確認の声はふつうの走りと同じく出すが、誘導の声の前6秒・後3秒は待たせ、ピッチの声とメトロノームは区間に入って10秒たつまで出さない（しくみの窓が休みをまたぐため）。しくみの始め・一時停止・再開・ほめる言葉は言わない。画面はいまの段・残り・次の区間を大きく出す。「開発用」の「模擬データで崩しの撮影を試す」は短い版を20倍で流す（`simulate.ts` の `demoDrill`。姿勢の崩しは作れないので、値が変わるのはピッチ・弾む・かかと・付け方の区間だけ）
- 「模擬データで試す」（ホームの「開発用」の中）：`simulate.ts` の `demoRun` を10倍の速さでセンサーの代わりに流し込む（ブラウザで画面と記録を確かめるため）

## 実機で確かめること

- しっかり付けた腰で、付け方の確認が鳴らないか（とくに着地の衝撃でのジャイロの細かい揺れ）。わざとゆるくした・腕・手・ポケットで鳴るか
- 前と後ろの見分け（着地直後に前後の加速度が負という仮定）
- 腰の位置と骨盤の回転による、上下動・ブレーキのずれ。ジャイロで直したブレーキ（brakingMs）と直す前（brakingFixed）のどちらがカメラ版の変化に合うか
- 疲れの見分け：ふつうのペースの走りで「いつもと違う度合い」が線（2）を超えないか、長い走りの後半で上がるか。1歩ごとの切れ目で数える有効接地時間が、毎秒50回に並べ直した値で足りるか
- iPhone の取れる回数と、画面が消えている間の取り方
- 外で：まっすぐ一定のペースで走って、速さで止まりすぎないか（GPS のゆれ・ビルや木の下）。信号の手前の減速・上り坂・インターバルで止まるか、止まるのが遅れて声が出ないか。±10% と、ならしの時定数（3秒）を記録で決め直す

- 練習：1回目のテンポの上げ方（1分ごとに 2.5%）に気づかず合わせられるか。メトロノームの音がずっと鳴っても邪魔にならないか、声と重ならないか。5〜8回目の止める間（2分ごとの割合）で、止まっても同じピッチが保てているか（結果の「音なし」）
- テスト：外の同じ道で、速さを合わせられるか（±5%）。4分の平均のばらつきが、月ごとの差より小さいか（同じ日に2回走って比べる）

確かめるときは、トレッドミルでスマホを腰に付けて走り、横に置いたカメラ版を答えにして比べる（製品としては外専用）。
