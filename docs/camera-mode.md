# カメラ版（トレッドミル）のしくみ

トレッドミルの横に置いたスマホ1台で骨格を推定し（MediaPipe Pose Landmarker、端末の中だけ）、崩れをその場で声で直す。本線。
コードは `src/modes/camera/`。数字とその根拠は `src/modes/camera/params.ts` の各定数の上の説明にあり、フォームの見方のページ（/theory/）はその値をそのまま表示する。
このページは流れと、どの数字がどこにあるかの地図。確かめた結果は `docs/validation-plan.md`。

## 走りの流れ

1. **置き方**（`SETUP`・`CORRECT`）：真横・高さ・全身が入る距離を声で案内する。真横から約8°以内（前側・後ろ側の値 `frontMax`・`behindMax`）。スマホの傾きセンサーで見下ろしを補正する（下向きと、大きく上を向いたときだけ）。
   置き方の画面に「ベルトの速さ（時速 km）」の欄がある（下の「速さ」）。
2. **2つの立ち方**：a「いつもの楽な立ち方」→ b「胸を開いて、肩を後ろに引いて、顎を軽く引いた立ち方」を3秒ずつ。直立の基準（首の角度・腰の高さ）は b で取る（目指す形を基準にし、いつもの猫背を基準にしない）。
   立ち姿勢の決まった線（`BASELINE.standingHead` 24°・`standingTrunk` 0°）は、b でも越えていたら知らせるだけ（測り直さない）。越えていなくても「まっすぐです」とは言わず、「胸を開いた姿勢を登録しました」と言う。
   直近5回の基準の真ん中から `BASELINE.slack` 以上甘い基準は使わない。胸・頭のセンサーをつないでいれば、同じ2つの立ち方がセンサーの物差しになる（`docs/sensor-mode.md`）。
3. **走り始め**（`src/core/params.ts` の `RUNNING`）：直近10秒（`ratioWindow`）のコマの8割が歩数で「走っている」になってから。ジョグの時速8.0では、走り出してから約10秒で始まる。
4. **正しいフォームへ整える**（`form.ts`、数字は `FORM`）：走り出して `FORM.from` 秒からは、正しいフォームの線と16秒平均で比べ、外れた項目を1つずつ声で直してもらう（線の内側に入ったら「その形です」）。
5. **仮の基準 → 今日の基準**：整え終わって30秒たまったら仮の基準（`FORM.early`）で崩れを見始め、60秒以上（`FORM.refAfter`）ためて今日の基準を作る（走り出して約3分。腰は `HIP_REF` の30秒〜3分）。崩れた秒は基準にためない。基準ができる前に走りが止まったとみたら、次に走り出したところから数え直す。
6. **走っている間**：今日の基準からの崩れ（`LIMITS`・`REL_LIMITS`）と、正しいフォームの線（`FORM`）の両方で見る。体全体・上体・頭は、正しいフォームの線で走り出しから最後まで見る。声をかけるのは `src/core/engine.ts` のしくみ（`docs/modes.md`）。
7. **結果**：声なしで保てた時間、良い・ふつう・悪いの割合、崩れ始め、よい例との差（速さごと）、次の一歩（`nextStep.ts`）、走り姿（主な速さの区間の実際の1周）。

## 見る項目

| 項目 | 測る値 | 今日の基準からの崩れ | 決まった線 |
|---|---|---|---|
| 猫背 | 上体の増えと「首の角度の増え ＋ `HUNCH.neckSlack`」の小さいほう（`coach.ts` の `hunchOf`） | `LIMITS.hunch` | なし（よい例の内側でも起きるので、基準からの増えでしか分からない） |
| 頭 | 首の角度（肩→耳 − 腰→肩）の増えと、頭の位置（肩→耳）の増えの小さいほう | `LIMITS.head` | `FORM.head`（首と頭の位置の両方が越えたとき） |
| 上体（前・起きすぎ） | 腰の中心→肩の中心の前傾 | `REL_LIMITS.trunk`・`trunkBack` | `FORM.trunk` |
| 体全体（前・起きすぎ） | 足首の中心→肩の中心の前傾 | `REL_LIMITS.body`・`bodyBack` | `FORM.body` |
| 腰 | 腰の高さ ÷ 脚の長さの下がり | `LIMITS.hip`（今日の基準ができるまで判定しない） | なし |
| 着地 | かかと − 腰の中心の前後 ÷ 脚の長さ（1歩ごとの山の、16秒の中央値。`landing.ts`） | `LIMITS.landing`（走り出しは仮の基準 `LANDING.early`） | `FORM.landing`（速さで補正した値。声にする） |
| 顎 | 耳→鼻の線の上向き | 測って記録するだけ | なし |
| 走りの数字 | ピッチ・上下動・腰の高さ・腕振り（`gait.ts`、`GAIT`） | 声はかけない（結果に出す） | なし |

- 走りの数字に声をかけないのは、走りの中のゆれや速さの変化と見分けられないため（仮想実験 `sim/result-gait.md`）。
- 頭の線の声は、直さずに走り続けると整える間の3回と、そのあと5分に1回（`FORM.tries`・`FORM.later`）。

## 厳しさ（ランナーのレベル）

線の厳しさは、ランナーのレベル（`src/core/level.ts`）で変える（`STRICT` と `applyStrictness`。初心者＝やさしめ、中級＝ふつう、上級＝きびしめ。レベルが分からなければ中級）。
点数も同じ線から出すので、良い姿勢の割合も同じだけ変わる。起きすぎの下の線と着地は、どのレベルでも同じ。
上級だけ、頭の正しいフォームの線を 首 32°・頭の位置 36° まで下げて、走り出しから頭が前に出ている人に整える間に知らせる（初心者 48°/52°、中級 46°/50°）。
線ごとの数字と根拠は `STRICT` の上の説明、記録と研究データに通した結果は `docs/validation-plan.md` の「猫背と厳しさ」。

## よい例（速さごと）

- よい例の範囲（`GOOD`）は、講師のよい例9本（アプリと同じ骨格の推定。素材は `docs/product.md` の「素材」）の いちばん小さい〜いちばん大きい値と真ん中。走っている間は声をかけず、結果の画面の「よい例との差」と次の一歩に使う。
- 速さごとの範囲は `goodAt(kmh)`（`GOOD_SPEED`）：講師の速さ（時速12km）を土台に、時速1kmあたり体全体・上体を 0.6° ずらす（Riglet 2024 の同じ人で +0.81°・+0.82°、人をまたいだ真ん中は約 +0.6°）。
  頭の位置はずらさず（速さで差なし）、首の角度は上体と逆向きに同じだけ。着地はずらさない（速さで補正済み）。講師の速さから離れるほど上下に 0.2°/km 広げ、時速7〜12km の間だけずらす。
  時速10〜12km（講師の例がある速さ）の外は仮（画面と /theory/ に「仮」と出す）。表は `sim/result-good-speed.md`。
- 線のうち速さで動かすのは、ベルトの速さを入れた走りの体全体の下の線（起きすぎ）だけ：その速さのよい例の下の端 −0.3°（`FORM_SPEED.bodyMinGap`）まで下げる（時速8km で約 3.5°）。上体・体全体の上の線と頭の線は動かさない（理由は `docs/validation-plan.md` の「速さごとのよい例」）。

## 速さ

- **ベルトの速さ**（`belt.ts`）：置き方の画面の欄に入れる（前回の値を覚える。空欄なら使わない）。走りの途中で速さを変えるなら、入れるのは走り出しの速さ（いまは区間ごとには入れられない）。
  入れた速さは、結果のよい例の範囲・走っている間の線（`applySpeed`）・足首のセンサーの速さの式の人ごとの合わせ（`docs/sensor-mode.md`）に使う。記録の events に `belt:kmh 9`、走り終わりに `speed:belt 9`（ベルトがなければ `speed:sensor`・`speed:camera`）。
- 使う順：ベルトの速さ（真）→ 足首のセンサーの速さ（人ごとに合わせたもの）→ カメラの速さの目安（脚/秒。時速に直す倍率 5.6 は脚の長さ 0.85m とした値で、人の脚の長さと置き方で ±10% ほどずれる）。
- **速さの見張り**（`landing.ts` の `SpeedGuard`、数字は `LANDING`）：速さの目安が今日の基準から ±15% を越えた秒は着地を比べず、20秒続いたら新しい速さで基準を作り直す。
  姿勢（頭・上体・体全体・腰）も、外れが `LANDING.postureAfter` 秒続いたら基準・線と比べず点数にも入れず、速さが変わったら姿勢の基準も作り直す。今日の基準をためている間も同じ見張りで見る。
  速さで姿勢がどれだけ動くかは `docs/research/posture-vs-speed.md`。

## 撮り方と記録

- 骨格を取るのは毎秒15コマまで。安定して走っている間は10秒のうち3秒だけ見る（`src/core/params.ts` の `POWER`）。URL に `?full=1` を付けると全コマ記録（線を変えて通し直すため。電池と熱のため、ふだんの走りでは付けない）。
- 「動画で試す」：横から撮ったランニングの動画を、カメラの代わりに流せる（直立の基準は仮のものになる）。スロー分析もある。
- 胸・頭・足首などのセンサーをつなぐと、カメラの判定と声はそのままで、センサーが振動で知らせ、値を記録に残す（`docs/sensor-mode.md`）。
- 記録の送り方は `CLAUDE.md` の「手順」。
