# カメラ版（トレッドミル）のしくみ

トレッドミルの横に置いたスマホ1台で骨格を推定し（MediaPipe Pose Landmarker、端末の中だけ）、崩れをその場で声で直す。本線。
コードは `src/modes/camera/`。数字とその根拠は `src/modes/camera/params.ts` の各定数の上の説明にあり、フォームの見方のページ（/theory/）はその値をそのまま表示する。
このページは流れと、どの数字がどこにあるかの地図。確かめた結果は `docs/validation-plan.md`。

## 走りの流れ

1. **置き方**（`SETUP`・`CORRECT`）：真横・高さ・全身が入る距離を声で案内する。スマホの傾きセンサーで左右の傾きを戻し、見下ろしを補正する（下向きと、大きく上を向いたときだけ）。下向き・上向きが10°（`pitchDownMax`）を越えたら「まっすぐ立ててください」と言う。左右の傾きは言わずに傾きセンサーで直す。
   真横は、前側・後ろ側の値（`yawSign`）を2秒（`yawSmooth`）ならして真横からのずれ（度）を見積もり（`yawCenter`・`yawPerDeg`。仮想実験の立った姿勢）、約5°以内（`yawIn`）に入るまで進まない。一度入ったら8°（`yawOut`）を越えるまでは外れたとしない（立って止まっていても値が数秒で2〜4°ぶんゆっくり動き、線の際で入ったり出たりしたため）。
   案内は向きと大きさを言う（`yawGuide.ts`）：スマホの位置が体の真横より前にずれていれば「スマホの位置が少し前です。もう少し後ろに動かしてください」のように後ろへ、後ろにずれていれば「前のほうへ」動かす（前後の位置のずれで、上下は別の案内）。15°（`yawFar`）より大きければ「大きく」、8〜15°は「少し」、5〜8°は「あと少しです…ほんの少し」。同じ向きの案内は大きさが変わっても言い直さず6秒（`hintRepeat`）おき。案内のあとで真横に入ったら「真横になりました。スマホはそのまま動かさないでください」。
   体を見る向きはスマホの位置で決まり、回すだけでは体が画面の端に寄るだけなので、「回して」ではなく「ずらして」と言う（仮想実験の向きも、スマホを体のまわりに回り込ませたもの。回すだけの置き方は試していない）。画面には、ずれの目安をメーター（後ろ側から ← 真横 → 前側から、緑の帯が5°以内）で出す。
   真横の案内を出している間は、映像の上にスマホを動かす向きを大きな橙の矢印で出す（ゆっくり点滅。動きを減らす設定では点滅しない。「大きく」は矢じり2つ、「あと少し」は短い矢印。下に「スマホをこちらへ」）。向きは画面の左右で、前すぎるときは走る人の顔の向き（鼻と耳。直近2秒のコマの8割以上がそろったとき）と反対、後ろすぎるときは同じ向き（`yawGuide.ts` の `yawArrowDir`）。背面カメラの映像は左右を反転せずに出すので、画面の左右はスマホの後ろから見た実際の左右と同じ（前面カメラは鏡のように反転して見せるので矢印も逆）。顔の向きが分からないときは矢印を出さず、声とメーターだけ。案内のあとで真横に入ったら、緑のチェック（「真横です」）を1.5秒出す。走っている間は出さない。
   人による違い（同じ置き方で約±3°）があるので、真横に置いても人によっては少し動かすよう言われる。根拠の数字は `params.ts` の `SETUP` の上。
   傾きセンサーが使えない間は、体全体・上体・着地を正しいフォームの線と比べない（下の「スマホの向きと傾き」）。
   置き方の画面に「ベルトの速さ（時速 km）」の欄がある（下の「速さ」）。
   置く・2つの立ち方・走り出すのを待つ間の画面は、映像と骨格を文字でふさがない（上に1行、下（横置きでは右）に大事な1行とベルトの速さ、ほかは「くわしく」にたたむ）。
   映像のふちを、全身が入っていれば緑・足りなければ橙で囲み、頭・足が切れている側のふちを塗る。点線は、頭と足が入ってほしい線（`framing.ts` の `EDGE`）。何が足りないか（体が映っていない・頭が切れている・足が切れている・体の一部が見えていない）を1行で出す（`framing.ts`）。
   置く間の声は、足りないものを言い分け、どう直すかまで言う（映っていない `guideNone`・頭 `guideHead`・足 `guideFeet`・両方 `guideBoth`・一部 `guideHidden`）。
   全身（`framing.ts` の ok）が入って人の体の形らしいのが2秒続くまでは、次へ進まない（足首が画面の下のふちから出たまま進むことがあった）。走り出したあとは画面を暗くする。
2. **2つの立ち方**：a「いつもの楽な立ち方」→ b「胸を開いて、肩を後ろに引いて、顎を軽く引いた立ち方」を3秒ずつ。直立の基準（首の角度・腰の高さ）は b で取る（目指す形を基準にし、いつもの猫背を基準にしない）。
   立ち姿勢の決まった線（`BASELINE.standingHead` 24°・`standingTrunk` 0°）は、b でも越えていたら知らせるだけ（測り直さない）。越えていなくても「まっすぐです」とは言わず、「胸を開いた姿勢を登録しました」と言う。
   直近5回の基準の真ん中から `BASELINE.slack` 以上甘い基準は使わない。胸・頭のセンサーをつないでいれば、同じ2つの立ち方がセンサーの物差しになる（`docs/sensor-mode.md`）。
   b の首・頭の位置は、頭の正しいフォームの線を「b からの差」で見るのにも使う（コーチの `open`。下の「スマホの向きと傾き」）。
3. **走り始め**（`src/core/params.ts` の `RUNNING`）：直近10秒（`ratioWindow`）のコマの8割が歩数で「走っている」になってから。ジョグの時速8.0では、走り出してから約10秒で始まる。
   歩数を数えるのは全身が見えたコマだけなので、体が入っていない・頭や足が切れていると、走っても始まらない。待つ間に案内を言い直すとき（15秒ごと）、確かめた映り方が全身でない、または直近 `WAIT.window` 秒で全身が入っていたコマが `WAIT.seenMin` を切っていれば、「走り出すと始まります」ではなく映り方の声（下の「映り方の声」）を言う。記録の events に `wait:<見え方> ok <割合> fps <コマ数>`。
   骨格のコマが少ないと（毎秒 `WAIT.slowFps` 未満）、全身が見えていても始まらないことがある（自分の全コマ記録を間引いて通すと、毎秒3コマでコマの間がゆれると始まらなかった）。画面に「処理が追いつきません」と出す（声の言葉はまだない）。P20 lite の毎秒のコマ数は未確認。
4. **正しいフォームへ整える**（`form.ts`、数字は `FORM`）：走り出して `FORM.from` 秒からは、正しいフォームの線と16秒平均で比べ、外れた項目を1つずつ声で直してもらう（線の内側に入ったら「その形です」）。
5. **仮の基準 → 今日の基準**：整え終わって30秒たまったら仮の基準（`FORM.early`）で崩れを見始め、60秒以上（`FORM.refAfter`）ためて今日の基準を作る（走り出して約3分。腰は `HIP_REF` の30秒〜3分）。崩れた秒は基準にためない。基準ができる前に走りが止まったとみたら、次に走り出したところから数え直す。
   **落ち着いてからの基準**（`BASE_SETTLE`、2026-11-10 本人の決め）：走り出して6〜10分の形で、今日の基準（猫背・頭・上体・体全体・腰）を作り直す。それまでの基準は、体が温まって走りが落ち着く前の形でできるため
   （トレッドミルの走りが落ち着くのに約6〜7分。研究の根拠は `params.ts` の `BASE_SETTLE` の上）。ためるのは、正しいフォームの線の内側にいた秒で（足りない項目は線の内側に寄せる）、基準からの崩れ（6秒平均が線を越えた）の間と、速さが外れている間はためない。
   速さが変わったとみたら、新しい速さの基準ができてからため直す。アプリは安定して走っている間 10秒のうち3秒しか見ないので、30秒（`min`）たまらなければ15分（`until`）まで待ち、それでも足りなければ走り出しの基準のまま。10分より短い走りも走り出しの基準のまま。
   落ち着く前の崩れは、正しいフォームの線（走り出し10秒から）と走り出しの基準からの崩れで見る。基準はどれも正しいフォームの線の内側に寄せ、腰は腰の決まった線（下の「腰」）より下にしない。
   着地の基準は、速さで作り直すしくみ（`LANDING`）があるので、作り直さない。
6. **走っている間**：今日の基準からの崩れ（`LIMITS`・`REL_LIMITS`）と、正しいフォームの線（`FORM`）の両方で見る。体全体・上体・頭は、正しいフォームの線で走り出しから最後まで見る。声をかけるのは `src/core/engine.ts` のしくみ（`docs/modes.md`）。
   どの姿勢の声も、平均（基準からの崩れは6秒、正しいフォームの線は16秒）が線を越えたうえに、**1秒ごとの値が線の外に `CUE.sustain`（3秒）続いたときだけ**（下の「一瞬の崩れは言わない」）。
7. **結果**：声なしで保てた時間、良い・ふつう・悪いの割合、崩れ始め、よい例との差（速さごと）、次の一歩（`nextStep.ts`）、走り姿（主な速さの区間の実際の1周）。
   走り姿に重ねるのは「正しいフォーム」（その1周の上体と首の角度を、その走りの速さのよい例 `goodAt` の真ん中に直した形。脚と腕の振りはそのまま。`figure.ts` の `correctFrames`）と「次の一歩」（その1周の、次に意識する1つだけを直した形）。
   ホームの走り姿は、後ろの灰色が正しいフォーム、上の緑の点線が前回の走り（いちばん多かった姿勢の1周、`nextStep.ts` の `mainStride`）。まだ走っていなければ見本だけ。
   過去でいちばん良い走り（良い姿勢の割合が最大の走り）は、手本として出さない。良い・ふつう・悪いは、その日の自分の基準からの崩れで分けたもので、基準が猫背の日は「良い」も猫背のまま。前はそれを「あなたのベスト」と見せていて、前かがみの形を手本のように見せていた（2026-11-07 本人の決めで外した）。
   いちばん上のひとこと（`summary.ts`）は、崩れ始めが見つかればその時刻を言う。見つからなくても「大きく崩れずに走れました」と言うのは、良い 70% 以上・悪い 15% 以下・声が1分に1回以下の走りだけ（`params.ts` の `SUMMARY`）。それ以外は良い・悪いの割合をそのまま言う（判定した秒がなければ「姿勢を判定できた時間がありませんでした。」）。
   崩れ始めは序盤より点数が下がった時刻なので、走り出しから崩れていた走り（11-06 12:27、良い 16%・悪い 53%・声17回）では見つからず、前は「大きく崩れずに」と出ていた。

画面の「終える」（左上）：どの段階（読み込み・置く・2つの立ち方・走り出しを待つ・走る・止まった・画面を暗くした間）でも、いちばん上に重ねて出す。
走り出す前は1回のタップで終わる。走っている間（止まっている間も）は、1回目で「もう一度押すと終わります」に変わり、4秒以内にもう一度押すと終わる（ベルトの操作などで触れて終わらないため）。
終えると、走りが始まっていれば記録を残して結果の画面へ、始まっていなければ記録だけ残してホームへ戻る。
なぜ：走っている間（画面を暗くした間）は、左上の字のない ✕ を4割の濃さで出していただけで見つけにくく、読み込みの間は「準備しています…」の覆いの下で押せなかった（暗くしない設定のときも、映像があとから重なって押せなかった）。センサーランの長押し（1.5秒）は、ポーチの中で触れて終わらないためで、台に置くカメラ版には使わない（腰スマホは長押しでなく、✕と下の「終える」を1回押す）。

## 映り方の声（置く・2つの立ち方・走り出しを待つ・走っている間）

人がカメラから出たり入ったりするので、映り方が変わるたびに声で言う（`framing.ts` の `FramingVoice`、数字と根拠は `params.ts` の `FRAME_SAY`）。

- 言葉：置く間は直し方まで（上の1.）。2つの立ち方・待つ・走っている間は、本人はトレッドミルの上にいるので起きていることだけ：
  「足が映っていません。」`frameFeet`・「頭が映っていません。」`frameHead`・「頭と足が映っていません。」`frameBoth`・「体の一部が見えていません。」`frameHidden`、
  映っていないときは走っている間と同じ「画面から外れました。トレッドミルの真ん中に戻ってください。」（`lost`）。切れていると言ったあとに全身が戻ったら「全身が入りました。」（`bodyIn`）。
- 連呼しない：切れているのが `hold`（3秒。走っている間は `ABSENCE.lostSay` の5秒）続いたら言う。映り方の声どうしは `gap`（6秒）あけ、同じことの言い直しは `repeat`（15秒。走っている間は `repeatRun` 60秒）。
  記録の events に `frame:<映り方>`。
- 走っている間の「画面から外れました…」（`engine.ts`、骨格が見えなくなって5秒）との重なり：その声を出すときに頭・足が切れていると分かればそちらの言葉にし、映り方の声が少し前に同じことを言っていれば言わない（`frame:<映り方> lost skip`）。
  走っている間は、切れたコマを見たら間引かずに毎コマ骨格を取る（続いた時間を数えるため）。
- 2つの立ち方の言い直し（`BASELINE.repeat`）は、体が映っていない・一部が見えていない間はしない（映り方の声に任せ、言い直した回数にも数えない）。
- **「全身が入りました」の確かめ**：いまのコマが全身で、2秒（`okHold`）のどのコマも全身（コマは4つ以上）、脚の高さ ÷ 体幹 が 0.9〜2.4、頭から足までの大きさのゆれが1.3倍以内のときだけ。置く間はスマホが1.5秒静止してからのコマだけ数える。
  - なぜ：2026-11-06 19:35 の記録（Android）で、人が画面から消えたコマ（骨格なし）で「全身が入りました」と言った（直前2秒の「映っている」の割合だけで決めていた）。
    同じ記録と 19:09 では、足首が画面の下のふち（高さ 640 の 627）より下（628〜649）なのに「見えています。全身が入りました。」と言い、画面の「足が切れています」と食い違っていた（「映っている」は画面のふちを見ていなかった）。
  - 体の形と大きさのゆれの線は、自分の記録14本で人が映っていたコマの範囲から広めに取った。人のいない部屋の記録はなく、見間違いをどれだけ外せるかは未確認。
  - 自分の記録14本（11-02〜11-06）に通すと、iPhone の長い走り（11-03〜11-05、11-06 12:27）では走っている間に映り方の声は一度も出ず、Android の2本（19:09・19:35）は足首が下のふちにかかっていて、待つ間・走っている間に「足が映っていません」が15〜60秒ごとに出た（通した点は傾きを直したあとの点なので、画面のままの点とは少し違う）。

## 見る項目

| 項目 | 測る値 | 今日の基準からの崩れ | 決まった線 |
|---|---|---|---|
| 猫背 | 上体の増えと「首の角度の増え ＋ `HUNCH.neckSlack`」の小さいほう（`coach.ts` の `hunchOf`） | `LIMITS.hunch` | なし（よい例の内側でも起きるので、基準からの増えでしか分からない）。本人だけの候補 `STAND_REF` の `hunchAbs` を記録だけ |
| 頭 | 首の角度（肩→耳 − 腰→肩）の増えと、頭の位置（肩→耳）の増えの小さいほう | `LIMITS.head` | `FORM.head`（首と頭の位置の両方が越えたとき。b からの差か、向きを直した値で。`form.ts` の `headOver`）。立ち方 a からの差 `STAND_REF` を記録だけ |
| 上体（前・起きすぎ） | 腰の中心→肩の中心の前傾 | `REL_LIMITS.trunk`・`trunkBack` | `FORM.trunk` |
| 体全体（前・起きすぎ） | 足首の中心→肩の中心の前傾 | `REL_LIMITS.body`・`bodyBack` | `FORM.body` |
| 腰 | 立脚中期のコマだけの、腰の中心 → 立脚側の足首の高さ ÷ 立脚側の脚の長さの下がり（`geometry.ts` の `midstance`、`coach.ts` の `hipOf`。膝の曲がりも測って記録だけ） | `LIMITS.hip`（今日の基準ができるまでと、立脚中期のコマのない秒は判定しない） | `HIP_ABS`（記録だけ。声にしない）。立ち方 a からの下がり `STAND_REF` も記録だけ |
| 着地 | かかと − 腰の中心の前後 ÷ 脚の長さ（1歩ごとの山の、16秒の中央値。`landing.ts`） | `LIMITS.landing`（走り出しは仮の基準 `LANDING.early`） | `FORM.landing`（速さで補正した値。声にする） |
| 顎 | 耳→鼻の線の上向き | 測って記録するだけ | なし |
| 走りの数字 | ピッチ・上下動・腰の高さ・腕振り（`gait.ts`、`GAIT`） | 声はかけない（結果に出す） | なし |

- 走りの数字に声をかけないのは、走りの中のゆれや速さの変化と見分けられないため（仮想実験 `sim/result-gait.md`）。
- **立った姿勢 a からの差を記録だけ**（2026-11-11 本人の決め。`params.ts` の `STAND_REF`、`coach.ts` の `StandWatch`、記録の1秒の `samples[].stand`）。声・判定・点数には使わない。
  - なぜ：今日の走りの基準からの崩れだけで見ると、走り出しから崩れている人には何も言えない。その日の本人の立った姿勢（2つの立ち方の a＝いつもの楽な立ち方）を基準にすれば、
    「立っているときより頭がどれだけ前か」「立っているときより腰がどれだけ低いか」が分かる。決まった線（a を引かない値）は、スマホの置き方で値がずれる量（自分の記録で日によって上体 約7°・腰の高さ 0.034）が、よい形と崩れの差より大きく使えなかった
  - 値（どれも直近6秒の、測れた1秒の平均。3秒に足りなければ出さない）：
    `headVsA` 頭の位置（手前側の肩 → 耳の傾き。頭の項目と同じ値）− a（度）、`neckVsA` 首の角度 − a（度）、
    `hipVsA` a の腰の高さ（腰の中心 → 低いほうの足首の高さ ÷ 脚の長さ。立っているので両脚がまっすぐ）からの、立脚中期の腰の高さの下がり（%）、`hipVsAAll` 同じく全部のコマの腰の高さ（`hipRatio`）の下がり（%）、
    `hipEar` 腰の中心 → 両耳の真ん中の線の前傾（度、a を引かない）、`hunchAbs` 猫背の決まった線の候補（上体 ≥ 5° かつ 頭の位置 ≥ 45° なら 1。そのときの上体 `trunk` と頭の位置 `headLean` も残す）
  - 入れる秒：歩数で走っていて、速さが外れていない秒。スマホの向きが真横から 25° より離れた秒は入れない。a を引かない値（`hipEar`・`hunchAbs`）は、傾きセンサーが使えなかった秒も入れない。
    a を測っていない（動画で試す）ときは、a を引く値を null にする。a の腰の高さは events の `pose:a` の `hip`（2026-11-11 から。前の記録は、採点の道具が a を測った3秒の行から出す）

## スマホの向きと傾き（置き方に強くする）

数字はどれも仮の値で、根拠は `params.ts` の `FORM`（頭の説明）・`HEAD_OPEN`・`CAM_YAW` の上。

- 置き方で大きくずれるのは頭（首・頭の位置）だけ。仮想実験（Riglet の30本）で、前側に1°ずれるごとに首 +0.78°・頭の位置 +0.61°。上体・体全体・腰・着地はほとんど変わらない。
  左右の傾き（roll）を直さないと、上体・体全体はそのまま1:1でずれる。
- **頭は2つの見方**で線（`FORM.head`）と比べ、どちらかで首と頭の位置の両方が越えたら「頭が前」：
  - ① **胸を開いた立ち方（b）からの差**：走っている頭 − b の頭 + `HEAD_OPEN`。同じ置き方で測った差なので、置き方のずれがほぼ消える。基準は b（目指す形）で、走り出しの頭ではない（走り出しから前に出ている頭も知らせる）。
    `HEAD_OPEN` は、自分の記録6本の立った頭の真ん中（首 21.6°・頭の位置 17.5°）。その6本で、走りの首は日によって 32.7〜42.6° と10°ちがったが、走り − 立ち は 12.8〜15.3° にそろった。動画で試すときは b がないので②だけ。
  - ② **線そのもの**：走っている間の前側・後ろ側の値（yawSign）から向きを見積もり（`CAM_YAW.perDeg`）、前側にずれた分を差し引いて比べる（後ろ側は直さない）。
    見積もった向きが前側に `STRICT[level].form.headYawMax`（上級 4°、中級・初心者 21°）を越えたら比べない。上級の線（32°/36°）は、仮想実験で前側に約3.6°ずれただけで、よい例の真ん中で走る人に声が出るため。
  - 今日の基準の頭は、線の内側にいた秒か、①と②のきびしいほうで線の内側に入る値（走り出しの前に出た頭を基準にしない）。

  自分の走りは、走っている間の yawSign が +0.06〜0.08（前側に約13〜17°と見積もる）と、立っているとき（+0.01）より大きく、上級の②はほとんど比べない。

    基準の頭が①の線の内側に寄るので、基準からの頭の崩れの声は 38 → 48回（6本、計約152分）に増えた。中級は前とほぼ同じ。
  - 未確認：b（胸を開いて顎を引く）の頭が「まっすぐ立って」の頭より小さく出れば①は厳しくなる。自分以外の人の 走り − 立ち の違い。トレッドミルで向きだけを変えた記録での②の量。

## 厳しさ（ランナーのレベル）

線の厳しさは、ランナーのレベル（`src/core/level.ts`）で変える（`STRICT` と `applyStrictness`。初心者＝やさしめ、中級＝ふつう、上級＝きびしめ。レベルが分からなければ中級）。
点数も同じ線から出すので、良い姿勢の割合も同じだけ変わる。起きすぎの下の線と着地は、どのレベルでも同じ。
上級だけ、頭の正しいフォームの線を 首 32°・頭の位置 36° まで下げて、走り出しから頭が前に出ている人に整える間に知らせる（初心者 48°/52°、中級 46°/50°）。上級の線そのもの（上の②）は、見積もった向きが前側 4° までのときだけ比べ、ふだんは b からの差（①）で見る。
線ごとの数字と根拠は `STRICT` の上の説明、記録と研究データに通した結果は `docs/validation-plan.md` の「猫背と厳しさ」。

## よい例（速さごと）

- よい例の範囲（`GOOD`）は、講師のよい例9本（アプリと同じ骨格の推定。素材は `docs/product.md` の「素材」）の いちばん小さい〜いちばん大きい値と真ん中。走っている間は声をかけず、結果の画面の「よい例との差」と次の一歩に使う。
- 速さごとの範囲は `goodAt(kmh)`（`GOOD_SPEED`）：講師の速さ（時速12km）を土台に、時速1kmあたり体全体・上体を 0.6° ずらす（Riglet 2024 の同じ人で +0.81°・+0.82°、人をまたいだ真ん中は約 +0.6°）。
  頭の位置はずらさず（速さで差なし）、首の角度は上体と逆向きに同じだけ。着地はずらさない（速さで補正済み）。講師の速さから離れるほど上下に 0.2°/km 広げ、時速7〜12km の間だけずらす。
  時速10〜12km（講師の例がある速さ）の外は仮（画面と /theory/ に「仮」と出す）。表は `sim/result-good-speed.md`。
- 線のうち速さで動かすのは、ベルトの速さを入れた走りの体全体の下の線（起きすぎ）だけ：その速さのよい例の下の端 −0.3°（`FORM_SPEED.bodyMinGap`）まで下げる（時速8km で約 3.5°）。上体・体全体の上の線と頭の線は動かさない（理由は `docs/validation-plan.md` の「速さごとのよい例」）。

## 速さ

- **ベルトの速さ**（`belt.ts`）：置き方の画面の欄に入れる（前回の値を覚える。空欄なら使わない）。走りの途中で速さを変えるなら、入れるのは走り出しの速さ（いまは区間ごとには入れられない）。
  入れた速さは、結果のよい例の範囲・走っている間の線（`applySpeed`）・足首のセンサーの速さの式の人ごとの合わせ（`docs/sensor-mode.md`）に使う。記録の events に `belt:kmh 9`、走り終わりに `speed:belt 9`（ベルトがなければ `speed:sensor`・`speed:camera`）。
- 使う順：ベルトの速さ（真）→ 足首のセンサーの速さ（人ごとに合わせたもの）→ カメラの速さの目安（脚/秒。時速に直す倍率 5.6 は脚の長さ 0.85m とした値で、人の脚の長さと置き方で ±10% ほどずれる）。
- **速さの見張り**（`landing.ts` の `SpeedGuard`、数字は `LANDING`）：速さの目安が今日の基準から ±15% を越えた秒は着地を比べず、20秒続いたら新しい速さで基準を作り直す。
  姿勢（頭・上体・体全体・腰）も、外れが `LANDING.postureAfter` 秒続いたら基準・線と比べず点数にも入れず、速さが変わったら姿勢の基準も作り直す。今日の基準をためている間も同じ見張りで見る。
  速さで姿勢がどれだけ動くかは `docs/research/posture-vs-speed.md`。

## 撮り方と記録

- 調整用の記録（`log.ts`）には、コマごとに判定の数字・骨格の点のほか、前側・後ろ側の値（小数3桁）、傾きセンサーの左右の傾き（使えなければ -999。変わったら events に `roll:ok`・`roll:none`）、
  worldLandmarks からの向きと上体・首・頭の位置を残す。立ち方ごとに events に `pose:a`・`pose:b`（頭・上体・首・頭の位置・前側・後ろ側の値・腰の高さ `hip`）。
- 骨格を取るのは毎秒15コマまで。安定して走っている間は10秒のうち3秒だけ見る（`src/core/params.ts` の `POWER`）。URL に `?full=1` を付けると全コマ記録（線を変えて通し直すため。電池と熱のため、ふだんの走りでは付けない）。
- 「動画で試す」：横から撮ったランニングの動画を、カメラの代わりに流せる（直立の基準は仮のものになる）。スロー分析もある。
- 胸・頭・足首などのセンサーをつなぐと、カメラの判定と声はそのままで、センサーが振動で知らせ、値を記録に残す（`docs/sensor-mode.md`）。
- 記録の送り方は `CLAUDE.md` の「手順」。

## Android で使うとき

使わない（2026-11-06 の本人の決め）。テスト用の Android（Huawei P20 lite）では骨格が毎秒2.4〜2.6コマしか取れず、走り出しの判定が約67秒遅れた。遅い機種には合わせない。くわしくは `docs/validation-plan.md` の「Android は使わない」。
