## 製品

### 誰に売るか

- 本線は、トレッドミルのカメラ版。24時間ジムのチェーン本部に、1店舗月1万円前後で売る。
- パーソナル系のジムと、路上向け（センサー4個）は外した。
- `~/Downloads/runformcoach_plan.md`（フェーズ2で屋外センサー4個）は、ここにある決定より前の古い計画。

### 入り口と料金の形

入り口は3つ。ホームのいちばん上で「トレッドミル／腰スマホ／センサーラン」を選ぶ。声かけのしくみは3つで共通（`docs/modes.md`）。

| 入り口 | 料金 | 役割 |
|---|---|---|
| スマホ1台（腰） | 無料 | 走っている最中の声かけを体験してもらう入口 |
| トレッドミルのカメラ（家のトレッドミルも可） | 月1,000円 | 姿勢まで見られる本命 |
| センサー | 別売りの買い切り | 路上・トラックで姿勢まで見る |
| ジムの会員 | 無料（ジムが払う） | 無料版の人がジムへ行く流れを作る |

### 無料のスマホ版

- 置き場所は腰（ウエストポーチ・ランニングベルト）だけ。ベスト・胸・リュックは対象外。使うのは外を走るときだけで、トレッドミルではカメラ版を使う（2026-10-12 に決めた。仕様は `docs/phone-spec.md`）。
- 声で直すのはピッチ1つに絞る。
- 姿勢はほとんど見えない。だからこそ精度が要る（外れた声をかけると戻ってこない）。走っている最中と走った後に、「姿勢はトレッドミルやセンサーで見られる」と正直に見せる。
- 画面が消えても動かすため、iPhone アプリにする（Capacitor などで今のウェブアプリを包む）。自分で試すだけなら App Store の審査は要らない（Xcode で入れる）。

### センサー版

- 誰のためか：路上やトラックで走る、本気でタイムを縮めたいランナー・トライアスリート。コーチに見てもらえるのは一瞬で、1人で走ると自分が見えない。動画を後で見ても、走っている最中には分からない。この穴を埋める。カメラが届かない場所なので、ここではセンサーが要る。
- カメラ版の項目は減らさない。カメラ版は「全身が見えるので、より高度な判定ができる」扱い。センサーにしか測れない項目もあるので、「それぞれ得意な項目がある」と見せる（項目の表は `docs/sensor-mode.md`）。
- 知らせ方は**振動**（2026-10-15 に決めた）。声は同じ内容でも「言われた」感が残り、イラっとすることがある。振動は何も言わずに気づかせられ、イヤホンも要らない。カメラ版は体に何も付けないので声のまま。
- Web Bluetooth が使えるのは Mac・Android の Chrome と、iPhone では Bluefy などの対応ブラウザだけ（iPhone の Safari は使えない）。人に配るときは、Bluefy に頼らず iPhone アプリ（Capacitor など）に包む。App Store で配れる形にもなる。

## モデル（判定）の方針

2026-11-06 にプロの視点の見直しを出し、本人が「速さごとのよい例を持つモデルにしよう。その他も提案どおり。ただし記録を作るのは私」と決めた。下はその決めと、それまでの決めをまとめたもの。

1. **外れた声は信頼を失う。** 項目を増やすより当たる精度を優先し、迷ったら声をかけない側に倒す。
2. **基準は正しいフォーム。走り出しの癖も「ふつう」にしない。**
   - 走り始めが崩れていたら、そこへ戻しても意味がない（2026-10-20 本人）。カメラ版は走り出しに正しいフォームの線（`FORM`）へ整え、整えたあとの形を今日の基準にして崩れを見る。
   - 走り出しから頭が前に出ているのは、それ自体がよくないので最初から言う（2026-11-05 本人）。カメラ版の上級の頭の線（首 32°・頭の位置 36°）と、頭のセンサー（おでこに付ける）の走り出し5秒からの知らせはこのため。
   - 胸・頭のセンサーは、走り出しの形ではなく、目指す形（2つの立ち方の「胸を開いた立ち方」）と比べる。
3. **線はアプリと同じ骨格の推定で測った値で決める。** 研究データの印の値をそのまま使わない（点の位置が違う）。人による違いが大きい項目は、外れた声にならない幅を取る。
4. **よい例は速さごとに持つ**（2026-11-06）。講師のよい例（時速10〜15km、7本が12km）を土台に、研究データの「同じ人が速さを変えたときの変わり方」でずらす（`goodAt`）。講師の例がない速さは仮。よい例では声をかけず、結果の画面でよい例との差を主役に出す。
5. **固定の線より、人ごとの較正を基準にする**（2026-11-06）。その日の本人の較正（2つの立ち方・走り出し・ベルトの速さ）を基準にし、集団から決めた線は安全網にする。いまあるのは、2つの立ち方（猫背の向きと物差し）、ベルトの速さの入力、足首のセンサーの速さの式の人ごとの合わせ（`src/modes/sensor/speedFit.ts`）。
   本人1人の記録で線を決める過学習と、講師の速さとの食い違いが、実際に使うと頭の指摘が多く出る原因だったため。
6. **骨格を手本にセンサーを合わせ続ける**（2026-11-05 本人「全てにおいてそう」）。トレッドミルで同時に取った記録が届くたびに、項目ごとにカメラとセンサーを突き合わせて線を見直す（`npm run compare:sensor`・`npm run replay:sensor`）。
   手本にするのは骨格が強い項目（姿勢の角度・着地の位置・腰の高さ）。時間の細かい項目（接地時間など）は、走りながらのカメラ（約14コマ/秒）の1歩より 100Hz のセンサーのほうが細かいので、多くの歩の平均かスロー動画を手本にする。横から映すので、左右の傾きと奥の脚は骨格が弱い。
7. **カメラの置き方に強くする（いちばん上の要件。分析中）。** 真横でない・距離や高さが違う・追いかけて撮る、のどれでも使える作りを目指す。いまは置き方の案内（真横から約8°以内・高さ）と見下ろしの補正で守っている（`docs/camera-mode.md`）。斜めや見下ろしで角度が大きくずれるのは、実際に踏んだ罠（`CLAUDE.md`）。動画の素材（下）はこの検証の材料。
8. **数字には根拠を付ける。** 研究データ、仮想実験（`sim/`）、実機の記録のどれかで確かめる。推測で埋めず、確かめていないことは「未確認」「仮」と書く。線を動かす前に、正解つきの記録があるかを確かめる。
9. **正解つきの記録は本人が作る**（2026-11-06）。確かめ走（`npm run drill:pose`）と答えつきの記録（`npm run drill`）。手順は `docs/validation-plan.md`。
10. **一度に意識できるのは1つ。** 声かけは1つずつ。知らせは外れたときだけ、戻ったら止め、だんだん減らす。
11. **言葉は起きていること（現象）を言い、直し方は体の外に注意を向ける。**
    - 原因は決めつけない：接地が長いときは「接地が長くなっています」と言い、「腰が落ちています」とは言わない（大また・かかとからの着地でも長くなる）。
    - 直し方は「目線を少し先に」「ピッチを少し上げて」、前かがみには「胸のライト」「上から吊られる」のたとえ（効率や衝撃にはたとえが効く）。顎・首など部位を動かす指示は走りが硬くなるので、走っている間は言わない（止まって形を作る2つの立ち方の案内だけ）。
    - 決まった形を直すときは部位を言うほうが効いた研究もある（Moore 2019）ので、着地は「体の真下に足を下ろして」と言う。言葉の一覧と理由は `src/core/phrases.ts`。
12. **同じ項目の知らせは1時間に20回まで**（`src/core/params.ts` の `LIMIT.perHour`。20 は仮の値）。知らせない間も測って記録する。知らせをだんだん減らす決まりはまだ作らない（回数を数えるだけ）。くわしくは `docs/sensor-mode.md` の「長い走りでの知らせの上限」。
13. **GPS は記録だけ**（センサーラン）。坂で知らせを変えるかをあとで決めるため。知らせには使わない。緯度・経度は残さない。
14. **足す仕組みは最小にする**（シンプルイズベスト）。ただし文書は情報を欠かさず、食い違いのないように整理する。

## これからの声かけの工夫（まだ作っていない）

- 言い方を段階的に変える
- その人がいつも崩れる時刻の少し前に声をかける
- 「外れた」音と「戻った」音を続けて鳴らさない

作ったもの：「声なしで保てた時間」を結果の主役にする、1回の走りで直す項目は1つ（ランナーのレベル）。
