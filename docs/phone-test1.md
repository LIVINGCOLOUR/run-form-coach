# 実機テスト①の手順（トレッドミル、1人・約30分）

スマホ版（腰）とカメラ版（横に置いたもう1台）を同時に記録し、スマホ版の測り方と付け方の確認を確かめる。
何を確かめるかは `docs/phone-spec.md` の「精度の確かめ方」。記録は `npm run compare` で比べる（このページの最後）。

区間の見分けは、**区間のあいだに15秒、ベルトのふちに立って休む**ことに頼っている。休みを入れないと、区間の名前を当てはめられない。
区間の順番と数は、比べる道具（`src/modes/phone/compare.ts` の `TEST1`）と同じにしてある。変えるときは両方を直す。

## 用意するもの

- スマホ2台：腰に付ける1台（スマホ版）と、横に置く1台（カメラ版）。どちらも「日付と時刻を自動設定」をオンにしておく（2台の時計が近いほど合わせやすい）
- ランニングベルト（ウエストポーチ）。ゆるめられるもの
- 腕に付けるアームバンド（なければ、その区間は手に持つ）
- 前にポケットのあるパンツ
- スマホを立てる台。トレッドミルの真横、2〜3m 離して、頭から足まで入るように

## 走る前

1. トレッドミルの速さを、楽に話せるくらいのペースに決める。**最後まで同じ速さ**（速さを変えると、ピッチや上下動の変化が走り方の変化と混ざる）。速さはメモしておく
2. 横のスマホでカメラ版を始める。走る前の案内に従い、ベルトの上で横向きに立つ
3. 腰のスマホでスマホ版を始め（ホームの「トレッドミルで試す（実機テスト）」。「スマホ版をはじめる」は外用で、GPS が取れないと判定を止めてしまう）、ベルトにしっかり付ける
4. **ベルトを止めたまま、カメラに映る場所でその場ジャンプを3回**（1秒半に1回くらい）。そのあと10秒じっと立つ。2台の時刻を合わせる手がかりになる

## 走る（合計 24 分 ＋ 休み）

各区間のあとは、ベルトを動かしたまま、**両足をベルトの左右のふちに乗せて15秒立つ**。付け方を変える区間の前はベルトを止めてよい。
休みも付け替えも、**カメラに映る場所で**（カメラ版は、映らない時間が30秒続くと終わってしまう）。

| 順 | 区間 | 長さ | 走り方 | スマホの付け方 |
|---|---|---|---|---|
| 1 | ふつう | 6分 | いつもの走り。スマホ版はここで走り始めの自分（基準）を作る | 腰にしっかり |
| 2 | ピッチを落とす | 3分 | 速さはそのまま、歩幅を大きくして足の回転をはっきり遅く（1割ほど。170歩/分なら150台）。スマホ版がピッチの声をかけても続ける | 腰にしっかり |
| 3 | ふつう（戻す） | 2分 | いつもの走りに戻す | 腰にしっかり |
| 4 | わざと弾む | 3分 | 足の回転はそのまま、上に弾むように走る | 腰にしっかり |
| 5 | ふつう（戻す） | 2分 | いつもの走り | 腰にしっかり |
| 6 | ゆるい | 2分 | いつもの走り | ベルトをゆるめ、スマホが揺れるくらい（落ちない程度） |
| 7 | 腕 | 2分 | いつもの走り | アームバンドで二の腕（なければ手に持つ） |
| 8 | ポケット | 2分 | いつもの走り | パンツの前ポケット |
| 9 | 腰に戻してふつう | 2分 | いつもの走り | 腰にしっかり（付け直したあとに、付け方の確認が鳴らないか） |

- 6〜8 では、スマホ版が「スマホがしっかり付いているか…」「腰のベルトに付けてください」と言うことがある。それが確かめたいことなので、そのまま続ける
- 付け替えで画面に触れたら、スマホ版が止まっていないかだけ見る（止まっていたら、その区間から先は記録がない。止まった区間を報告する）

## 走り終わったら

1. ベルトを止め、**もう一度その場ジャンプを3回**（時計の進みのちがいを確かめる手がかり。カメラ版は走っている間は間引いて撮るので、写らないこともある）
2. カメラ版とスマホ版を終える
3. 書き出す
   - カメラ版：結果の画面の「調整用の記録を書き出す」（またはホームの「直近の記録を書き出す」）。ファイル名は `rfc-年月日-時分.json`
   - スマホ版：結果の画面の「調整用の記録を書き出す」（またはホームのスマホ版の「直近の記録を書き出す」）。ファイル名は `rfc-phone-年月日-時分.json`
4. 2つのファイルと、トレッドミルの速さ、気づいたこと（区間を飛ばした・順番を変えた・アームバンドの代わりに手で持った など）を渡す

## 比べ方（受け取った側がやる）

```
npm run compare -- rfc-phone-….json rfc-….json
```

`compare-out/<スマホのファイル名>/` に次を置き、表を画面にも出す。

| ファイル | 中身 |
|---|---|
| `report.md` | 関門の目安（ピッチ ±2歩/分・上下動とブレーキの向き・付け方の確認）、時刻の合わせ方、区間ごとの表 |
| `chart.svg` | ピッチ・上下動・ブレーキを、時間をそろえて並べた図（スマホは1秒ごとの線、カメラはかたまりごとの点） |
| `bursts.csv` | カメラのかたまり（骨格を続けて取れた最長4秒）ごとの値と、同じ時間のスマホの値 |
| `seconds.csv` | スマホの1秒ごとの値（ピッチ・上下動・ブレーキ・付け方の手がかり）と区間 |

- 時刻：2つの記録を「ふつうの時刻」に直してから、動きの強さ（スマホは加速度、カメラは腰の高さの揺れ）がいちばん似るずれを探す。最初のジャンプと、立つ↔走るの切り替えが手がかり。合わないときは `--offset 秒`（カメラの時刻 = スマホの時刻 + 秒）で手で決める
- 区間：スマホの加速度で、休みに区切られた走りを見つけ、上の表の順に名前を当てはめる。数が合わないと番号だけになる。そのときは `--labels normal1,slow,normal2,bouncy,normal3,loose,arm,pocket,normal4` のように、走った順に名前を渡す（飛ばした区間は抜く）
- ピッチ：カメラは、足首が一番前に出た瞬間の間隔から測り直す。区間の始めの10秒は比べない
- ブレーキ：カメラにはブレーキそのものがないので、着地で足首が腰より前に出た量（オーバーストライド）を目安にする。上下動は、カメラは脚の長さに対する割合。どちらも、最初の「ふつう」からの向きだけを比べる
- 付け方の確認：走りの中では1回鳴ると止まるので、記録した手がかりで区間ごとに最初からやり直して、手順書の答えと比べる。手がかりの中央値・90%も出すので、線（`params.ts` の `MOUNT`）の合わせ直しに使う
