# 判定の精度を上げるための検証データ

公開の骨格検知モデル（MediaPipe）で関節の位置は取れる。
しかし、スマホ1台で横から撮った映像から「フォームの崩れ」を正確にとらえるところまでは届いていない。
原因は、このアプリが判定したいこと（この走りはここが崩れている）の**正解が付いたデータが世の中にない**こと。

## 方針

- 骨格検知のモデルはそのまま使う。自前で学習させるのではなく、関節の角度から「崩れ」と判定する**しきい値の調整**を中心にする。
- しきい値の調整なら大量のデータは要らない。**数十本の動画**でかなり進む。目安は5〜10人で、体格・性別・走力をばらけさせる。
- 届くのは、はっきりした猫背やオーバーストライドを捕まえられるところまで。疲れて少しずつ出る小さな崩れは、もっと多くの人数と本数が要る。

## コーチに見せる前の自分での確認

- わざと崩すと声が出る
- ふつうに走って声が出すぎない
- スマホの置き方を少しずらしても結果が変わらない
- 30分動かして落ちない

## 自宅のトレッドミルでの「答えつき」の記録

走るのは1回、線を直すのは何回でも。走る日は、Mac の声で区間ごとに崩し方を指示し、どの時刻に何を崩したかが分かる記録を取る。
走らない日に、その記録を今の判定にもう一度通して採点し、線を変えては採点し直す。

- 走る：横の iPhone でカメラ版を、URL に `?full=1` を付けて開いて始め（全コマ記録。ホームの「はじめる」の下と、走っている画面に「全コマ記録」と出る。置き方と立った姿勢の基準まで済ませる）、腰のスマホでスマホ版を「トレッドミル」で始めてから、Mac で `npm run drill`。
  既定（2回目）は全体約34分半、走るのは約24分半（時速8.0は本人が楽に走れる速さ。1回目は31分・きつさ3）。戻しの区間は「走ったまま、フォームだけ戻して」で、歩かない：
  1. 歩き5分（時速5.0）→ 止めて、合図でジャンプ1回
  2. 起きた形で走り出す1分30秒：体を少し後ろに残した形で走り出し、アプリの声（「体が後ろに残っています…」）が聞こえたら、そのとおりに直して、直ったらその形で走る。
     声で直せるかは仮想実験では確かめられない。採点では「走り出しの声」に、整える声・「その形です」・「姿勢が整いました」が並ぶ
  3. ふつう4分（今日の基準ができる間。崩しが基準に入らないよう4分とる）
  4. 「崩し30秒 → 戻し30秒」を7回：頭を前に・下を向く・猫背・体ごと前に・腕を振らない・腕を横に振る・腰を落とす
  5. 着地の崩し（1分ずつ、そのあと戻し30秒）：
     - 大また・かかとから前に着く。見込みは、今日の基準よりかかとの前が +0.05 を越え、着地の声が出る（3R の動画の着地の崩しは +0.03〜+0.09）。
       ただし、3R の「前で着地」の例では速さの目安も +19% 変わり、速さが変わったとみて比べなかった。2026-11-02 のわざと前に着いた2区間（約12秒・約8秒）では、
       速さの目安はふつうの揺れの中だった。1分続けて、速さの目安が動かないかをここで見る
     - 走り出しの大また（今日の基準ができる前）：走り出して約2分（着地の仮の基準ができたあと。`LANDING.earlyCollect`）に、30秒以上大またで走る。
       仮の基準からの増えで声が出るのが正しい。2026-11-02 の約12秒の大また（ふつうより +0.15）は、通し直しで約95秒に声が出た。
       16秒の窓の中央値で見るので、10秒より短い大または声にならない
     - ピッチを約1割落とす（速さはそのまま）。Mac が afplay でメトロノームを鳴らす。Mac は走っている人のピッチをその場では測れないので、
       テンポはいつものピッチ（`--cadence`、既定 165 歩/分＝1回目の時速8km のふつうの区間）の 0.9 倍（149 歩/分）で決め打ち。
       見込みは +0.02〜+0.04 で、着地の声が出るのは半分ほど（仮想実験で 56%）。腰のスマホ版は、ピッチの声とメトロノームを出してよい（スマホ版の確かめになる）が、従うのは Mac の音
  6. 速さを変える（1分ずつ）：時速 9.0 → 10.0 → 8.0 に戻す（Mac が「トレッドミルを時速9.0にしてください」と言う）。どの声も出ないのが正しい。
     着地は、速さの目安が今日の基準から ±15% を越えた秒は比べず、20秒続いたら基準を作り直す（9km/h は約 +12% で比べ続け、かかとの前は約 +0.02 の見込み。10km/h は作り直す）。
     速さの目安が時速 1km あたりどれだけ変わるか、かかとの前がどれだけ前に出るか（自分の置き方での速さの当てはめ）を見る
  7. ふつう4分
  8. 止めて、スマホを三脚ごとトレッドミルと平行に、走る向きと反対へ約30cm動かし（向きは変えない。カメラ版は画面から30秒外れると走りを終えるので、20秒以内にベルトの真ん中に戻る）、
     時速8.0で2分走る。走っている間の前側・後ろ側の値（yawSign、1回目は +0.07〜0.08）が、置き方のずれなら約 −0.06 下がる。下がらなければ、点の取り方のずれ
  9. 歩き3分
  脚に負担の大きい崩しのうち、弾む・べた足は入れていない（`--steps` で足せる）。
  先に `npm run drill -- --dry-run` で時刻表を、`npm run drill -- --try` で声を確かめられる（`--try --steps slow` でメトロノームも鳴る）。区間の表と長さ・速さのオプション
  （`--upright`・`--cadence`・`--speeds 9,10`・`--moved` など。0 や none で外せる）は `scripts/treadmill-drill.mjs` の先頭
- 記録：`~/Developer/research-data/runs/drill-YYYYMMDD-HHMM.json`。区間の始まり（言い終えた時刻）と終わりを、Mac の時計のエポックミリ秒で残す。言うたびに書き直すので、Ctrl+C で止めてもそこまでは残る
- 採点：`npm run logs` で記録を取ってきてから、`npm run grade -- <drill-….json> <rfc-….json> [<rfc-phone-….json>]`。
  区間ごとに、崩しを見つけたか・区間の始まりから最初の声までの秒数・ふつうの区間の誤った声・戻しの区間で声が止まったかを、
  「そのとき（記録にある声）」「いまの線（今のコードに通し直した声）」「上書き（`--set head=7` などで線を変えた声）」の3つ並べて出す。
  カメラ版は、しくみが走り始めた時刻と、今日の基準（走り出しに正しいフォームへ整えたあとの形）を作った間（どの区間か）とその値も出す。正しいフォームの線で言った声には「整」が付く。歩きや崩しの区間が入っていたら、その基準では採点の数字を信じない。
  あわせて、走り出しの声（最初の区間の始まりから、今日の基準ができた1分あとまでにアプリが話した言葉。「姿勢は整っています」と言ったか、整える声に従って直せたか）と、
  区間ごとの着地の値（いまのコードに通し直した窓の値：手前の脚のかかとの前・速さの目安・速さで補正した値と、今日の基準からの増え）・前側後ろ側の値（yawSign）・着地の声を出す。
  速さを変えた区間に出た声は、誤りとして別に数える。着地の線は `--set landing=0.04`（基準からの増え）・`--set landingMax=0.08`（決まった線）・`--set landingSay=1`（決まった線を声にする）・
  `--set speedGuard=0.2` で変えて通し直せる。着地の値は骨格の点から測り直すので、点のある記録なら、撮ったあとに入れた着地の判定も通せる
  通し直しの確かめ（そのときの声が、撮ったときと同じ条件で通し直して出るか）は、いつも記録の始めから撮ったときの項目で通したものと比べる。
  カメラ版の走り始めは、直近10秒のコマの8割が歩数で「走っている」になってから（`RUNNING.ratioWindow` など）。ジョグの時速8.0では、走り出してから約10秒で始まる。
  基準は、走り始めて30秒〜3分のうち歩数で走っていた秒だけで作るので、最初のふつうの区間は、ベルトが速さに乗るまでの時間と合わせて4分あれば崩しの区間が入らない。
  `--running steps` で、カメラ版の1コマずつの「走っている」を歩数だけで決め直せる（その場で走るフリの見分けを入れて撮った記録を、いまの判定で通すとき）
- 通し直しの限り：カメラ版は、ふだん（`?full=1` なし）は撮ったときに骨格を取ったコマ（安定して走っている間は10秒のうち3秒）だけが記録にあり、線を下げて「もっと細かく見たはず」になった秒は足せない。
  全コマ記録（`?full=1`）なら走っている間の毎コマ（毎秒15コマまで）があり、毎コマで通し直す。`--thin` を付けると、同じ記録をふだんの間引きに通し直し、間引いたときに声が遅れる・抜けるかを比べられる。
  30分ぶんで約3万行、JSON で約11MB、送るとき（gzip）は約4MB（送り先の上限は64MB）。電池と熱のため、ふだんの走りでは付けない。
  スマホ版は届いたコマすべてが残っているので、ほぼ撮ったときのとおりに通せる（記録の値の丸めで、線の際の秒がまれに変わる）
- 時計：iPhone・スマホ・Mac は、どれも時刻を自動で合わせている前提。ジャンプの「はい」から、記録で大きく動き始めるまでの秒数を採点の表に出す（ふつうは 0.3〜0.8 秒）。大きくずれていたら `--camera-offset` / `--phone-offset` で直す。
  合図の前に跳んでしまうと、その動きを拾って前にずれて出る。直す前に、崩しの区間の始まりで角度が変わった時刻（頭を前に出した時刻など）とも合っているか確かめる
- 採点の見本：`node scripts/treadmill/make-sample.mjs <フォルダ> [--full]` で、区間の記録と作りもののカメラ版・スマホ版の記録を作る（採点の道具を試すためだけのもの。線の根拠にはしない）
- 走りの数字（ピッチ・上下動・腰の高さ・腕振り。`src/modes/camera/gait.ts`、声はかけない）：足首と手首のセンサーを付けて撮ると、センサーの値と並べて確かめられる。
  2026-11-02 の記録で、カメラのピッチは足首のセンサーと8秒ごとに相関 0.95、上下動はピッチを下げた区間で増え、腕は肘を伸ばした・大きく振った区間で値が変わった。
  接地時間は、カメラの割合では足首のセンサーの変化を追えなかったので測っていない。まだ確かめていないこと：腰の高さを立った姿勢で割った値が、
  研究データのふつうの走り（`GAIT.typical`）と同じ物差しになっているか（アプリの点では立った姿勢が 1.01〜1.03）、腕の値の、よい例の範囲
- 頭の線（`FORM.head`）：カメラだけでは、頭が少し下がっただけ（頭のセンサーで 6〜8°）なのか、ふつうの揺れなのかを分けられない（2026-11-02、`sim/result-head-line.md`）。
  頭のセンサーを付けて撮ると、カメラの首の角度の16秒平均と相関 −0.93 で合うので、頭の崩しの区間が本当に崩れていたか（どれだけ前に出たか）の答えにする。
  線を変えるときは、仮想実験の表（ふつうの値からの高さ・誤った声・気づく割合）と、`--set headNeck=… --set headLean=…` で通し直したふつうの区間の声の両方を見る
- ベルトの速さは、途中で変えるなら記録に残す（Mac の声の区間か、手のメモ）。カメラの速さの目安は、同じ人の速さの変化をほぼそのまま追う
  （仮想実験で、目安の比 ÷ ベルトの比 0.93〜1.01、`sim/result-overstride.md` の ①）。足首のセンサーの脚の振りの速さはベルトより小さく変わる（振り +1% でベルト約 +1.8%）ので、
  2026-11-02 の 振り +22〜26% はベルト約 +45〜50% で、カメラの目安の +50% ほどと合う。確かめるには、ベルトの速さの記録と並べる。
  今日の基準をためている間に速さを変えると、基準は新しい速さで1分ためてからになる。その間にわざと崩した区間は基準に入るので、崩しは基準ができてから（走り出して4分より後。速さを変えたなら、変えてから2分より後）にする

## 猫背と厳しさ（2026-11-03 の走りで確かめたこと）

- **猫背はカメラで見える。ただし今日の基準からの増えとして。** 胸のセンサー（走り始め〜約10分。そのあとはずれた）を答えにすると、
  わざとの猫背60秒は 胸 +9.8°（6秒平均）。カメラの6秒平均の増えは 上体（腰→肩）+4.8°・首の角度 +6.5°・頭の位置 +11.7°。
  ふつうの区間（175窓）との分かれ方（AUC）は 上体 0.985・腰→耳の線 0.988・首の角度 0.89、頭だけ前に出した区間（胸は動かない）とは 上体 0.96・首の角度 0.37。
  そこで猫背は「上体の増え」と「首の角度の増え ＋ 2°」の小さいほう（`hunchOf`）で見る（ふつうとの AUC 0.98、頭だけ前とは 0.90。上体ごと股関節から倒したときは 2° で頭打ち）。
  この走りの猫背の上体は16秒平均で 8.2° で、講師のよい例（4.8〜9.5°）の内側なので、決まった線では見ない。
- **前の版で声が出なかったわけ**：①上体の決まった線（12°）に届かない。②走りが「止まった」とみられ（足を前に出す区間、記録の約296秒）、今日の基準をため直していた間に猫背が入っていた
  （基準ができたのは 515秒で、猫背の秒も基準に混ざっていた）。いまは、整え終わって30秒たまったら仮の基準（`FORM.early`）で崩れを見て、崩れた秒は基準にためない。
- **厳しさはレベルで変える**（`params.ts` の `STRICT`。初心者＝やさしめ、中級＝ふつう、上級＝きびしめ）。線ごとの数字と根拠は `STRICT` の上の説明。
  記録した走りに通した結果（`sim/strictness.sim.ts` → `sim/result-strictness.md`。見る項目はすべて）：

  | | 前の版（いまの初心者の線、猫背なし） | 初心者 | 中級 | 上級 |
  |---|---|---|---|---|
  | 11-03 ふつうの区間の声（10分あたり） | 1.2 | 1.8 | 2.4 | 4.1 |
  | 11-03 わざとの猫背 | 声なし | 猫背 7.8秒 | 猫背 7.8秒 | 猫背 6.6秒 |
  | 11-03 頭だけ前 | 46秒 | 46秒 | 46秒 | 15.6秒 |
  | 11-03 良い姿勢 | 83% | 77% | 70% | 37% |
  | 2本（11-03・10-19）のふつうの区間の声（10分あたり） | 2.1 | 3.1 | 3.5 | 5.9 |
  | 研究データ59本の誤った声（10分あたり、`sim/result-coach-strict.md`） | 1.24 | 1.24 | 2.51 | 4.04 |
  | 同じく、正しいフォームの線の声（整える間に声が出た走り / 基準のあとの10分あたり） | 4本 / 0.13 | 4本 / 0.13 | 5本 / 0.20 | 13本 / 0.54 |

  上級だけ、頭の正しいフォームの線を 首 32°・頭の位置 36° まで下げた（初心者・中級は 48°/52°・46°/50°）。走り出しからいつも頭が前に出ている
  （本人の決め：それ自体がよくないので、最初から言う）ので、よい例（講師9本、首 22〜30.9°・頭の位置 29.9〜37.8°）のすぐ外に置き、整える間に知らせる。
  いつもの頭（2026-11-03〜05 の16秒平均の真ん中 首 33°・頭の位置 37°）は、首はよい例より前だが、上体がよい例より起きていて頭の位置はよい例の上の端の内側なので、
  頭の位置の線はよい例の真ん中と上の端の間。仮想実験（`sim/result-head-start.md`）で、いつもの頭で走り出すと 92% で整える間（約22秒）に声が出て、
  よい例の真ん中で走る人にも頭の線の声が10分あたり 1.35回出る（38°/42° では 0.05回）。記録した5本（`sim/result-head-runs.md`）では、11-03・11-05 は走り出し約21秒に声が出た。
  上級のふつうの区間の声は 38°/42° 4.9回 → 32°/36° 5.9回（10分あたり、2本の合計）、良い姿勢は 11-03 61% → 37%・10-19 38% → 16%。
  10-19 の「頭を前に」は、32°/36° では 1.1秒で声が出た（38°/42° では先に線の声を使っていたため15秒以内には出なかった）。頭の決まった線は、研究データの頭の印が線に届かないので、記録でしか確かめられない
  良い姿勢の割合は、通し直しの値（アプリの画面に出た 96% は、そのときの版の値）。研究データの誤った声はほとんどが頭（ほかの項目は 0.00〜0.02）。
- **まだ届いていないこと**：
  - 頭だけ前（11-03）は、どのレベルでも15秒以内に声が出なかった（初心者〜中級 46秒、上級 15.6秒）。頭のセンサーでは前に出たり戻ったりをくり返していたうえ、
    ベルトの速さは変えていないのに着地の速さの目安が ±15〜20% 揺れ、速さが外れたとみて姿勢を比べなかった秒が、基準ができたあとの 45% あった。
    姿勢を止めるまでの秒（`LANDING.postureAfter`）を 5 → 15 にすると比べない秒は 25% に減り、頭の声は約27秒になるが、速さを本当に変えたときの誤った声が増えるので、まだ変えていない。
    速さの目安の揺れそのもの（間引いて撮った秒の窓）を見直すのが先
  - 2026-10-19 の記録の崩し（下を向く以外）は、画面から外れて走りの整え直しに入っていた間で、線の高さでは変わらない
  - 2026-11-02 の2本は短く（4〜5分）、今日の基準ができる前に終わっているので、厳しさの確かめには使っていない

## 胸の震えをカメラの猫背の声にそろえる（2026-11-04 の走りで確かめたこと）

- 11-04（上級、崩しのないふつうの走り）で、カメラは「背中が丸まっています」を6回言い、胸が震えたのは1回だけだった（線 +8° のとき）。
  胸の値がある3回（センサーの値は記録の上限 約35分で 2453秒に止まる）では、声の前6秒の胸の増えは +5.4°・+6.3°・+3.9°（1.5秒続いた最大 +6.5°・+8.5°・+2.7°）。
- 胸の線を、カメラの猫背の線と同じくレベルごとにした（`src/modes/sensor/params.ts` の `HUNCH_BY_LEVEL`：初心者 +6°・中級 +5.5°・上級 +5°、hold 1.5秒、ずれの見張り slipDrift 8° のまま）。
  記録3本をコーチと胸の見分けに通し直した結果（`sim/chest-camera.sim.ts` → `sim/result-chest-camera.md`）：

  | 胸の線 | カメラの声に合った（初心者・中級 / 上級） | 外れ（10分あたり、ふつうの区間） | ずれの間の震え（10分あたり） | 11-04 に走ったときの声 |
  |---|---|---|---|---|
  | +8°（前の線） | 3/4 / 4/5 | 1.4（上級のカメラと比べて 0.8） | 6.1 | 1/3 |
  | +6° | 4/4 / 4/5 | 2.2 | 18.2 | 2/3 |
  | +5° | 4/4 / 4/5 | 2.7 | 21.6 | 2/3 |
  | +3°（1秒） | 4/4 / 5/5 | 5.8 | 34.4 | 3/3 |

  「外れ」はカメラの猫背の声から ±15秒より離れて震えたこと（11-04 の32分と 11-03 の前半5分）。11-04 の 1278秒の声は胸が +3° しか動かず、+3° / 1秒 まで下げないと合わない。
  カメラの猫背の値（6秒平均）と胸の増えは、わざとの猫背のある 11-03 で 相関 0.61（胸 ≈ 1.9 + 1.36 × カメラ）、ふつうの走りだけの 11-04 は、カメラの値がほとんど 0〜1° で相関が出ない（0.03）。
- 代わりに増えるもの：センサーがずれて線を越えたままの間は、見張りが置き直すまで（約75秒）鳴る回数が増える。わざとの猫背60秒（2回でも）はずれとみなさない（`sim/result-lean-slip.md`）。
- 走ったときに胸が大きく震えた 1331・1618・2093秒（傾き 77〜87°）は、胸も頭も数秒だけ大きく前に倒れたところ（何をしたかは記録からは分からない）。
- 1時間の走りでは、センサーの値が後半残らない（`SENSOR_LOG.maxChars`）。残り3回の声（2610・3374・3602秒）は確かめられていない

## 直立の確かめ（決まった線）

- 直立の3秒は、今日の基準ではなく決まった線（`camera/params.ts` の `BASELINE.standingHead` 24°・`standingTrunk` 0°）と比べ、越えたら「猫背になっています。背筋をまっすぐ伸ばしてください」と言って測り直す（2回まで）。胸・頭のセンサーの立った姿勢は、線の内側に入った3秒で覚える。
- 線は `sim/standing.sim.ts` → `sim/result-standing.md`：研究データ23人の立った姿勢（仮想のスマホ）と、背中を丸めた形（10° で 上体 +5.0°・頭 +11.6°）、自分の5本の直立。
  上体 0° はまっすぐ立った人の 96%・自分の5本が通り、10° 丸めた形を 78% 止める。頭は人による違いが大きく（4〜39°）、24° と合わせて、10° 丸めた形をすべて止め、まっすぐ立った人の 57% が1回目で通る。
  自分は上体が −4〜−8° と後ろ寄りに立つので、上体の線だけでは自分の 10° の丸まり（見込み −0.4°）に届かず、頭の線（見込み 約28°）で止まる
- 確かめていないこと：本当に猫背で立ったときのアプリの値（仮想の丸め方で見込んだだけ）。研究データの耳はアプリの耳の点と少し違う

## 速さごとのよい例（2026-11-06）

本人の決め：「よい例は速さごとに持つモデルにする」「固定の線より、人ごとの較正を基準にする」。

- **よい例の範囲**（`camera/params.ts` の `GOOD_SPEED`・`goodAt`）：講師のよい例9本（時速10〜15km、7本が12km。アプリと同じ骨格の推定）を土台に、
  研究データの同じ人の速さでの変わり方で、時速1kmあたり体全体・上体を 0.6° ずらす（Riglet 2024 で +0.81°・+0.82°、人をまたいだ真ん中は約 +0.6°）。
  頭の位置はずらさず（速さで差なし）、首の角度は上体と逆向きに同じだけ。着地はずらさない（速さで補正済み）。講師の速さから離れるほど上下に 0.2°/km 広げ、
  時速7〜12km の間だけずらす。時速10〜12km の外は仮。表と、研究データのふつうの走りとの比べは `sim/good-speed.sim.ts` → `sim/result-good-speed.md`。

  | 時速 | 体全体 | 上体 | 首の上の端 | 頭の位置の上の端 | 根拠 |
  |---|---|---|---|---|---|
  | 7（仮） | 3.0〜7.6 | 0.8〜7.5 | 34.9 | 38.8 | 講師12km からの外挿（Riglet の下から1割 6.9km の端） |
  | 9（仮） | 4.6〜8.4 | 2.4〜8.3 | 33.3 | 38.4 | 外挿（Riglet 楽 8.1km・速い 9.9km の間） |
  | 11 | 6.2〜9.2 | 4.0〜9.1 | 31.7 | 38.0 | 講師（10km 1本）と 12km の間 |
  | 12 | 7.0〜9.6 | 4.8〜9.5 | 30.9 | 37.8 | 講師のよい例そのもの（7本） |
  | 13・15（仮） | 6.8〜9.8・6.4〜10.2 | 4.6〜9.7・4.2〜10.1 | 31.1・31.5 | 38.0・38.4 | 真ん中は 12km のまま（RBDS で 12.6→16.2km は差なし、講師 15km の1本も内側）、幅だけ広げた |

  着地はどの速さでも −7%〜+9%。研究データのふつうの走り（よい例ではない）と比べると、上体は速さごとの範囲のほうがよく入る（Riglet 楽 30本：11本 → 22本）が、
  体全体は研究データの人がもともと講師より大きく、範囲を下げると「上に外れる」が増える（10本 → 23本）。講師との差は速さではなく走り方の違いとみて、そのまま。
- **線**：ベルトの速さを入れた走りでは、体全体の下の線（起きすぎ）だけを、その速さのよい例の下の端 −0.3° まで下げる（時速8km で 3.5°）。
  中級・上級の上体・体全体の上の線を同じだけ下げる案は、研究データ79本で線を越えた本数が増えた（中級 体全体 3→5・上体 3→7、上級 7→12・4→8）ので入れていない。頭の線は動かさない。
- **ベルトの速さの入れ方**：トレッドミルのカメラ版の置き方の画面に「ベルトの速さ（時速 km）」（前回の値を覚える。空欄なら使わない）。記録の events に `belt:kmh 9`、
  走り終わりに `speed:belt 9`（または `speed:sensor`・`speed:camera`）。走りの途中で速さを変えるなら、入れるのは走り出しの速さ（いまは区間ごとには入れられない）。
- **足首のセンサーの速さの人ごとの合わせ**（`sensor/speedFit.ts`）：切片 `STEP.speedA` の既定は RBDS の −0.183。ベルトの速さを入れた走りの1歩ごとの
  「ベルトの速さ − speedB × 振れ幅 ÷ 1歩き」の中央値を端末に残し、直近5回の中央値を使う（RBDS から ±0.6 m/s の外は入れ間違いとして抑える）。記録の events に `speedFit:A …`。
  記録2本に通した結果（通し直し。両足の1歩、走っていた間）：

  | 記録 | ベルト | RBDS の式 | 前の既定（+0.09） | この走りで合わせた speedA | 合わせたあと |
  |---|---|---|---|---|---|
  | 11-05 19:07 | 9.0（本人） | 8.0（7.5〜8.4） | 8.9 | +0.108（4988歩、左 0.069・右 0.150、前半 0.138・後半 0.083） | 9.0（8.5〜9.4） |
  | 11-04 20:05 | 約7（本人の平均、記録なし） | 5.9（5.3〜6.7） | 6.9 | +0.112（仮に 7.0 として） | 7.0（6.3〜7.7） |

  11-05 で合わせた +0.108 で 11-04 を見積もると 7.0 km/h（本人の申告とそろう）。左右で 0.08 m/s（約0.3 km/h）、前半・後半で 0.05 m/s 違う（付け方とベルトの加速）。
- **まだ確かめていないこと**：時速7〜9km のよい例（講師の記録がない。よい姿勢の走り手を同じ置き方で7・8・9km で1分ずつ撮れば埋まる）、
  カメラの速さの目安を時速に直す倍率 5.6（脚の長さ 0.85m とした値。自分の 10-19 の目安 1.3〜1.4 は 7.3〜7.9km で合う）、ベルトの速さを入れた走りが2本以上たまったときの合わせの安定、
  外（センサーラン）での見積もり（GPS の速さと並べて確かめる。GPS の速さは `runner.ts` の `onGps` に来るので、確かめたら `fitSpeedA` に渡せる）

## 動画の集め方

- **撮り方はアプリと同じにそろえる**: 三脚に固定したスマホで、トレッドミルを真横から撮る。高さと距離もそろえる。
- **走る人は正しいフォームでなくてよい**: 普通のランナーのクセがそのまま、よくある崩れの材料になる。
- **わざと崩してもらう必要はない**: 少し疲れるまで（20〜30分）いつも通り走ってもらえば、後半に自然に崩れる。これはアプリが捕まえたい「後半の崩れ」そのもの。
  判定は、正しいフォームの線と、走り出しに整えたあとのその人の形と比べて行う（全員が正しいフォームで走っている必要はない。外れていれば、それも材料になる）。
- わざと崩した動画（下を見る・背中を丸めるなど）は、判定が鳴るかの確認用に本人が数本撮れば足りる。

## 正解の付け方

- **コーチが走りを見ながら話した言葉を、同じ動画に録音する**。何秒のところで何が崩れているかが、そのまま正解になる。
- 数字で測れるもの（体幹の傾き、着地のすねの角度、上下動）は、研究の目安（見本に使っている Fukuchi 2017 のデータなど）と比べて判定する。
- 見た目で決めるもの（猫背など）は、コーチに一部を見てもらって基準をそろえる。

## 検証の仕方

- **基準を決めるのに使う人と、精度を確かめるのに使う人を分ける**（例：7人でしきい値を決め、残り3人で当たるかを確かめる）。
  同じ人の動画で調整と確認の両方をすると、精度が実際より高く見える。

## ネットにある走る動画

使えるのは次の確認までにとどめる。

- 判定が明らかな崩れ（「悪い例」の動画）に反応するか。逆に、きれいなフォームで鳴りすぎないか。
- 体格・服装・肌の色・明るさが違っても、骨格検知が崩れないか。

しきい値を決める材料には使わない。理由は次のとおり。

- 撮り方が違う（屋外、カメラが追いかける、斜め、編集やスロー）ので、角度の数値がずれる。
- わざとの崩れは大げさで、どこから鳴らすかの基準が決められない。
- どの瞬間がどう悪いかが分からず、結局自分で印を付けることになる。
- YouTube の利用規約は動画のダウンロードを原則禁止している。著作権法30条の4は解析のための利用を広く認めているが、映っている人の肖像の問題もある。製品にするときは、どのデータで作ったか説明できる状態にしておく。
