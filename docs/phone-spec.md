# スマホ版の仕様（案）

スマホ1台を体に付けて走り、走っている最中に直す無料版の仕様。
材料は `docs/research/phone-competitors.md`（競合の機能）と `docs/research/phone-methods.md`（研究、約60本）。数字と出典はそちらにある。

## 前提

- 置き場所：腰のランニングベルトが基本。体に密着するベスト・胸なら上体の前傾も見る（`docs/product.md`）。
- **腰のスマホで走りを測って、基準の機械と比べた研究は見つからなかった。** 研究の精度は、体にテープで留めた専用センサーでの値で、ベルトの中のスマホはこれより悪くなる。だから声にするのは、研究で効果が確かめられ、外れにくいものだけにする。
- 姿勢（猫背・頭）は見えない。そのことは走っている最中と後に正直に伝え、トレッドミル（カメラ）やセンサーへつなぐ。
- 画面が消えても動くよう iPhone アプリにする。Apple Watch のアプリは今回は作らない（ウォッチの機能をスマホ1台で実現する）。

## 全体の形

**声で直すのは「ピッチ」1つに絞る。** ピッチを上げると、上下動・着地のブレーキ・着地の衝撃がまとめて下がる（Heiderscheit 2011、Anderson 2022、Napier 2019）。項目を増やすより、1つを確実に直す。
上下動・ブレーキ・接地時間・リズムの乱れは、測って記録し、疲れの見分けと走った後のまとめに使う。

| 機能 | 走っている最中 | 走った後 |
|---|---|---|
| 1. 付け方の確認 | 走り始めに1回、おかしければ言う | 記録に印 |
| 2. ピッチの崩れ | 声とメトロノーム | グラフ |
| 3. ピッチを上げる練習（選んだ人だけ） | メトロノーム、だんだん減らす | 練習の進み |
| 4. 速さ・坂で判定を止める | 止めるだけ（声なし） | 止めた時間 |
| 5. 疲れの見分け | 声なし | 崩れ始め |
| 6. 上下動・ブレーキ・接地時間 | 声なし | グラフ |
| 7. 上体の前傾（ベスト・胸） | 決めてほしいこと 1 | グラフ |
| 8. フォームのテスト | なし | 月ごとの比べ |

## 機能ごとの仕様と実現方法

### 1. 付け方の確認

- **何をする**：ゆるい・向きがおかしい・途中でずれたら、「スマホがしっかり付いているか確かめてください」と1回だけ言い、その走りの記録に印を付ける。Huawei が同じことをしている。
- **実現方法**：
  - 重力の向きが、走っている間に大きく変わっていないかを見る（ずれ）。
  - 1歩ごとの上下の揺れの形が、くり返しになっているかを見る（自己相関の山の高さ）。ゆるいと形が崩れる。
  - ジャイロの、歩くリズムと関係ない細かい回転が大きくないかを見る（ゆるみ）。
- **外れても害が小さい**。フォームを誤って直させることがない。上下動とブレーキの数字はすべて付け方に左右されるので、最初に作る。
- **線**：研究の根拠はない。実機で、しっかり付けた・わざとゆるくした走りを比べて決める。

### 2. ピッチの崩れ

- **測り方**：今のまま（上下の加速度の自己相関、Moe-Nilssen 2004。1歩ずつの切れ目の間隔）。研究どおりで、直さなくてよい。
- **比べ方**：
  - 走り始めの自分と比べる。基準の区間は、最初の30秒〜3分で仮の基準を作り、5〜12分の平均ができたら置き換える。Clermont 2019 は、マラソンの 4〜14km を「いつもの走り」にしていた。走り始めの数分は、まだ体が温まらず走りが落ち着かないため。
  - 速さが基準から外れている秒は、判定しない（機能4）。
- **線**：基準より5%下がったら。5% は「体に悪い線」ではなく、「自分の走りが変わった」線。負担がはっきり増えたのは10%下げたとき（Heiderscheit 2011）で、測れる最小の差は約2.5歩/分（Adams 2016）。
- **知らせ方**：
  - 初めの1回だけ言葉で言う：「足の回転が落ちています。小さな歩幅で、軽く刻んでください。」
  - あとは、基準のテンポのメトロノームを数小節だけ鳴らす。戻ったら止める。
  - 言葉を何度もくり返さない（Van den Berghe 2022 の「外れたときだけ音で知らせる」形）。
- **ブレーキ・上下動の崩れも、この声にまとめる**：ブレーキや上下動が増えて、同時にピッチが下がっていれば、ピッチの声を出す。ブレーキ単独・上下動単独の声は、トレッドミルで確かめるまで出さない。

### 3. ピッチを上げる練習（選んだ人だけ）

- **何をする**：自分のピッチの +7.5% のメトロノームを鳴らして走る。2週間で8回、後半の4回は鳴らす時間を減らす。
- **根拠**：
  - Willy 2016：外を走りながら +7.5% に直し、30日後も保てた。
  - Bramah 2019：+10% を教えて、3か月後も保てた。
  - Crowell 2011、Bowser 2018：効果が長く続いた研究は、どれも後半で知らせを減らしていた。
- **テンポの変え方**：一気に上げず、気づかないくらい（1〜3%）ずつ上げてもよい（Van Dyck 2015）。
- 走った後に、練習の進み（何回目か、ピッチの変化）を見せる。

### 4. 速さ・坂で判定を止める

- **理由**：ピッチ・上下動・ブレーキは、どれも走る速さで変わる（van Oeveren 2019、Baker 2025、Wang 2020）。ペースを落としただけ・上り坂に入っただけで「崩れ」の声が出るのを防ぐ。
- **実現方法**：
  - 外：GPS の速さを、ゆっくりした変化だけ通るようにならしてから使う。基準の速さから外れた秒は「判定しない秒」にする（engine.ts の仕組みをそのまま使う）。
  - トレッドミル：GPS は使えない。走り出す前に速さを入れてもらうか、入れなければ「速さは変わらない」とみなす。
  - 坂：気圧計の高さの変化が大きい秒は判定しない。研究の根拠はない案で、実機で確かめる。
- **外れる幅（何%で止めるか）**：実機で決める。

### 5. 疲れの見分け（声なし）

- **測るもの**：
  - リズムの規則性：上下と前後の自己相関（Schütte 2015）
  - 3方向の揺れの割合
  - 有効接地時間：上下の加速度が1gを上回っている時間（Patoz 2021、誤差22ms以下）
- **使い方**：これらをまとめた「いつもと違う度合い」で、崩れ始めを見つける（Clermont 2019）。
  - 走った後の「崩れ始め」に出す。
  - そのうち、「その人がいつも崩れる時刻の少し前に声をかける」工夫（`docs/product.md`）に使う。
- **走っている最中は声にしない**。何をすれば直るかを言いにくく、接地時間は短いほど良いとも言えないため（Lussiana 2019）。

### 6. 上下動・ブレーキ・接地時間（声なし、記録とグラフ）

- **上下動**：今のまま（1歩ずつ2回積分、Gullstrand 2009）。値は重心の上下動より大きめに出るので、自分の基準との差だけを見る。
- **ブレーキ**：前後の加速度を1歩ずつ積分する今の方法は、研究で確かめられていない。
  - 1コマごとにジャイロ（Core Motion の姿勢）で向きを直してから積分するように直す。骨盤の前後の傾きで、重力が前後に漏れ込むのを防ぐため。
  - トレッドミルでカメラ版と比べて確かめるまで、声にしない。
  - いちばん近い研究は、骨盤のセンサー1個から機械学習で前後の力を出したもので、誤差は体重の6.4%だった（Baker 2025）。
- **接地時間**：機能5の有効接地時間。

### 7. 上体の前傾（ベスト・胸のときだけ）

- **測り方**：今のまま（立った姿勢からの傾き）。
- **研究が言うこと**：前に傾けて走ると、膝のお皿の関節の負担はむしろ減った（Teng & Powers 2014）。疲れると前傾が増える。
- 声にするかは「決めてほしいこと 1」。

### 8. フォームのテスト（後で）

- **何をする**：平らな道（またはトレッドミル）を、決まった速さで5分走る日を月1回作る。ピッチ・上下動・接地時間を前の月と比べる。COROS の Running Form Test と同じ形。
- **声はかけない。** 速さと道をそろえるので、速さの影響を受けずに比べられる。

## 入れないもの

| もの | 理由 |
|---|---|
| 左右差（接地時間のバランス） | 腰の加速度では、右足か左足かを17〜19%取り違えた（Benson 2019） |
| 着地の衝撃・負荷率 | 腰で確かめた研究がない。ベルトのゆるみで値が変わる |
| ランニングパワー・歩幅・上下動比 | GPS に頼る数字で、直す言葉につながらない。時計がもう出している |
| 骨盤の回旋・左右の傾き | 専用の腰のセンサーでも正しく測れなかった研究がある（Ruiz-Malagón 2023）。ベルトの中でスマホが回ると「骨盤が回った」に見える |
| 着地法・プロネーション・頭・腕振り | スマホ1台（腰・胸）では測れない（足や耳や手首のセンサーが要る） |
| 心拍を使う指標 | 心拍計が要る |

## 知らせ方の決まり

- **言葉は最初の1回、あとは音。** 同じ言葉をくり返さない。
- **外れたときだけ知らせ、戻ったら止める。** 「声なしで保てた時間」の考え方と同じ。
- **知らせはだんだん減らす。** 知らせに頼ると、なくなったときに戻る（Winstein & Schmidt 1990）。
- **1つに絞る**（ピッチ）。
- **言葉の選び方**：
  - 「静かに」「小刻みに」のような音やたとえの言葉は、衝撃を下げた（Phan 2017）。
  - ただ、特定の形を直すときは、体の部位を言うほうが効いた研究もある（Moore 2019）。ピッチには、たとえの言葉を使う。
- **設定を簡単に。** 220人の試験で、3人に1人が設定を間違えて知らせを受けていなかった（Van Hooren 2024）。付け方は自動で確かめ（機能1）、選ぶものは最小にする。
- 流している音楽に雑音をかぶせる方法（Van den Berghe 2022）は、iPhone ではほかのアプリの音楽をいじれないので使わない。こちらの音（メトロノーム）だけで知らせる。

## 精度の確かめ方（声にする前の関門）

トレッドミルで、スマホを腰・ベストに付けて走り、横に置いたカメラ版と比べる。

| 確かめること | 合格したら |
|---|---|
| ピッチがカメラ版と合う（±2歩/分） | ピッチの声を出す |
| わざとゆるく付けると、付け方の確認が鳴る | 付け方の確認を出す |
| ブレーキ・上下動が、カメラ版（と研究のデータ）の変化と同じ向きに動く | ブレーキ・上下動の声を考える |
| 前後の向きの見分け（着地直後に前後の加速度が負という仮定）が当たる | 前傾・ブレーキの符号を信じる |

## 作る順番

1. 付け方の確認（B）
2. 速さで判定を止める、基準区間を後ろへ（B）。トレッドミルの速さの入力は画面と一緒に作る
3. ピッチの声とメトロノーム（B）。メトロノームを鳴らすのに、声かけのしくみ（engine.ts）に「音を鳴らす」知らせを足す（A）
4. 疲れの見分けと、上下動・ブレーキ・接地時間の記録、ブレーキの向きの直し（B）
5. スマホの入り口の画面と iPhone アプリ化（B）。ここで実機で走れるようになる
6. ピッチを上げる練習、フォームのテスト（B）

5の前でも、模擬データでテストまでは進められる。声を出してよいかは、上の「関門」で決める。

## 決めてほしいこと

1. **上体の前傾（ベスト・胸）で声をかけるか。** 研究では、前傾は膝の負担をむしろ減らす。カメラ版は前かがみで声をかけている。案：スマホ版では声にせず、疲れのサインとして記録と走った後に出す。
2. **ピッチを上げる練習を入れるか**（選んだ人だけ、2週間・8回）。案：入れる。けがの予防の研究がいちばん厚い。
3. **トレッドミルで使うとき、速さを入れてもらうか。** 案：入れてもらう（入れなければ速さは変わらないとみなす）。
