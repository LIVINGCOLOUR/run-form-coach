# センサーモード（センサーだけで走るモードは仕様だけ。いまはカメラ版といっしょに使う）

体に付けたセンサーで走りを見て、崩れを**振動**で知らせて直すモード（声は補助。判断のしくみはカメラモードと共通）。
トレッドミルのカメラモードが本線で、センサーモードはその2本目の使い方。

## 誰のためか

- 路上やトラックで走る、本気でタイムを縮めたいランナー・トライアスリート
- コーチに見てもらえるのは一瞬で、1人で走ると自分が見えない。動画を後で見ても、走っている最中には分からない。この穴を埋める
- カメラが届かない場所なので、ここではセンサーが要る

## 2つのモード

声かけのしくみ（`src/core/engine.ts`）は共通にし、入り口と、見る項目の一覧だけをモードごとに替える。
カメラモードの項目は減らさない。カメラモードは「全身が見えるので、より高度な判定ができる」扱い。
センサーにしか測れない項目もあるので、「それぞれ得意な項目がある」と見せる。

| 項目 | カメラモード | センサーモード | センサーでの測り方（案） |
|---|---|---|---|
| 首（頭が前に出る） | ◎ | ◎ | 頭のセンサーの前への傾き（いまある。下を向いたのとは分けられない） |
| 上体の前傾 | ◎ | ◎ | 胸のセンサーの前への傾き（いまあるのは猫背） |
| 体全体の前傾（足首→肩の線） | ◎ | ― | |
| 腰の落ち込み | ◎ | ― | 腰にセンサーがないので測らない |
| 腕振り | ― | ◎ | 手首のセンサーの前後の振れ幅 |
| 左右差 | ― | ◎ | 両足首の接地の間隔・接地の強さの左右の差 |
| 着地の衝撃 | ― | ◎ | 足首のセンサーの、接地の瞬間の加速度 |

## センサー

自作する（構成は別メモ。XIAO nRF52840 ＋ LSM6DSV、1個約3,250円）。

- 付ける場所：両手首、両足首、首（首の付け根の後ろ側）、胸（心拍計の胸ベルト）の6か所
- 無線：BLE でスマホに直接送る。XIAO nRF52840 の技適（211-220207）の範囲で使う。SlimeVR の Smol Slime の独自無線（ESB）は技適の面でグレーなので使わない
- 送るもの：センサーごとに、時刻・向き（クォータニオン）・加速度。1秒に送る回数は試して決める（姿勢だけなら数十回、着地の衝撃には数百回要る）
- 6個の時刻をそろえる方法は、作りながら決める

## 知らせ方：振動

崩れたら、声ではなくノードを振動させる（2026-10-15 に決めた。声は「言われた」感が残りイラっとすることがある。振動は何も言わずに気づかせられ、イヤホンも要らない）。
判断は、できるだけ下の層に置く。詳しくは `hardware/sensor/docs/haptic.md`。

| 層 | 置くもの |
|---|---|
| センサーチップ（LSM6DSV16X の FSM / MLC） | 1ノードで決まる反射：着地、着地の強さ、ケイデンスの低下、腕振りの周期、「いつもの走り／崩れた走り」の2値分類 |
| XIAO | 振動のパルス、ケイデンス誘導（実際の着地に位相を合わせて 2% 速く叩く）、絶対の姿勢（SFLP）、ルールの受け取り |
| スマホ | ノード間の比較（首と胸の角度差、左右差）、ルールを作って配る、記録。`engine.ts` の「いつ知らせるか・直ったらほめる・だんだん減らす」はそのまま使い、出口を声から振動に替える |

- まず手首1個で、感じ取れるかを確かめてから広げる（走行中の振動の実績があるのは手首。足首は未確認）
- 「言葉で書いたルール（例：着地が外に流れたら右足首を叩く）をノードに流す」は、XIAO が解釈する JSON ルールから始める

## いまあるもの：カメラ版といっしょに使う（`src/modes/sensor/`）

トレッドミルのカメラ版で走りながら、自作のセンサーもつなげる。カメラの判定と声はそのままで、センサーは胸で猫背を、頭で頭が前に出たのを見てその場所を震わせ、値を記録に残す。
外ではカメラがないので、センサーの判定はセンサーだけで決める（カメラから受け取るのは、立った姿勢を取る時刻と「走っている」だけ）。カメラは、線を決めるための答えに使う。

- つなぎ方：ホームの「はじめる」の下の「センサーをつなぐ」で、場所ごとに「つなぐ」を押して名前を選ぶ（Web Bluetooth。ブラウザの決まりで1個ずつ、押したときだけ）。一度選んだものは、`getDevices` があるブラウザなら次から押さずにつなぐ。走っている途中で切れたら、押さずに3回までつなぎ直す
- iPhone の Safari は Web Bluetooth がないので、つなげない（枠に Bluefy で開くよう出す）。センサーなしでも、カメラ版はそのまま使える
- 付ける場所とセンサーの対応は `params.ts` の `SLOTS` だけで決める（今は 頭=1、胸=2、左手首=4、左足首=3、右足首=6、右手首は空き。手首はカメラ（左から撮る）に見える左に付ける）
- 崩れの見分け（`lean.ts` の `LeanDetector`、数字は `params.ts` の `HUNCH`（胸）と `HEAD`（頭）。胸と頭は同じしくみで、線だけ違う）：
  - 立った姿勢：カメラが直立の基準を取った3秒の、そのセンサーの加速度の平均の向き
  - 走る前傾：カメラが歩数で「走っている」とみた時間で、走り出して10秒あとからの30秒。この間に立った姿勢から傾いた向きの平均を「前」とし、前への傾き（符号つき）の真ん中の値を走る前傾にする（胸はふつうの走りで 約12〜16°、頭は 約1〜15°）。横に傾いた・後ろに反ったのでは増えない
  - 基準：走る前傾から始め、線の下にいる間だけ時定数60秒で今の傾きへゆっくり寄せる。ベルトの上でセンサーが少しずつずれていくのを吸うため（2026-11-02 20:23 の走りで、胸の傾きが3分半で約15°増えたのに、カメラの上体は 2〜8° のまま。寄せないと2分すぎから胸が鳴り続けた）。線を越えている間は寄せないので、崩れたままなら知らせ続ける
  - 走っている間、前への傾きが基準 + margin（胸 8°、頭 18°）を1.5秒続けて超えたら、その場所を1秒震わせ、超えたままなら4秒ごとに震わせ直す。線の下に戻れば止まる
  - 寄せることの代わり：ゆっくり進む崩れは吸ってしまう。胸で +12° の猫背なら約50秒、+15° なら約75秒、+20° なら約2分より時間をかけて進むと鳴らない（数秒〜数十秒で丸まるのは鳴る）
  - 頭のセンサーは、首が前に出たのと下を向いた（うなずいた）のを同じに見る（カメラの顎の角度と r −0.97）
  - カメラの今日の基準（整えたあとの形）は走り出して3分以上たってからできるので、センサーの走る前傾はそれを待たない
- 確かめた結果（`npm run replay:sensor` に記録を通した。数字は2本の走りと Mac のテストだけから）：
  - 胸：20:23 の走り（上体はずっとまっすぐ）で、寄せる前は16回（約44回/10分）鳴ったのが3回（約8回/10分。そのうち2回はカメラの上体も数秒で +4〜5° 動いたところ）。わざと猫背にしたテスト（Mac、40秒）は寄せても同じく9回、ふつう・胸を張っては0〜1回
  - 頭：カメラの答え（`FORM.head`：首 > 48° かつ 頭の位置 > 52°）と5秒の窓で比べて、18:43 は一致 98%（崩れを見つけた 89%）、20:23 は一致 88%（100%）。首が 40° 未満（はっきり崩れでない）のときに鳴らしたのは2本で1回。margin 14 なら見つける割合は上がるが外れが増え、20 なら外れはなくなるが 18:43 の崩れの2割を見逃す
- 記録：走った記録（`RunLog` の `sensors`）に、100Hz のうち1件おき（50Hz）の生の値を、センサーごとに約1秒ずつ base64 で入れる（形は `core/types.ts` の `SensorLog`、戻すのは `log.ts` の `decodeBlock`）。5個で約4.7KB/秒、30分で約8.4MB、上限は約35分ぶん（`SENSOR_LOG.maxChars`）で、超えたら値は残さず、知らせた記録だけ残す。胸と頭それぞれの立った姿勢・走る前傾・知らせた時刻と傾き（胸はいちばん上の `stand`・`runLean`・`cues`、頭は `head` の中。頭を見る前の記録には `head` がない）、センサーごとの抜けと電池も入る。カメラの記録の events には `sensor:stand`・`sensor:runLean`・`sensor:hunch`（胸）と `sensor:headStand`・`sensor:headLean`・`sensor:head`（頭）が残る。時刻はカメラの記録と同じ時計（`rows` の t）

## 今の入力との対応

`coach.ts` の入力（`CoachInput`）は、センサーからも作れる。

| 入力 | カメラモード | センサーモード |
|---|---|---|
| `present`（人がいるか） | 骨格が映っているか | センサーがつながっているか |
| `moving`（走っているか） | 脚の動き | 足首のセンサーで数えた歩数 |
| `m`（角度） | 骨格の点から（`geometry.ts`） | センサーの向きから（新しく作る） |
| `frame`（骨格33点） | 渡す | 渡さない。走り姿のアニメーションはカメラモードだけの機能 |

## 判定の基準

カメラモードと同じ考え方を使う。

- 走る前に、まっすぐ立って3秒止まる（今の直立の基準）。センサーモードでは、各センサーが体のどの向きに付いているかの補正も、このときに取る
- 上体などは、走り始めの自分の平均からの増え方で判定する（今の `REL_LIMITS` の考え方）

## コードでやること（作り込みのとき）

1. センサーから角度を作る入り口を作る
2. `coach.ts` の見る項目の一覧（今は `ITEMS` に4つ固定）を、モードごとに渡す形にする。項目を足すときは、線（`params.ts`）と声かけの言葉（`phrases.ts`）を足す
3. 人に配るときは、Bluefy に頼らず iPhone で Bluetooth を読めるよう、今のウェブアプリを iPhone アプリの殻（Capacitor など）に包む。App Store で配れる形にもなる
4. 1ノードで決まる反射はルールにしてノードへ送り、スマホからは「今この部位を1回叩く」だけを送る（案）。叩く入り口（0xFFE3 の書き込み）は `ble.ts` の `buzz` にある

## 試し方

- 自作のセンサーが動くかは、Mac の Chrome（Web Bluetooth）で、今のウェブアプリのまま確かめられる。iPhone では Bluefy（Web Bluetooth に対応したブラウザ）で開く。iPhone の Safari は Web Bluetooth に対応していない
- 自分の iPhone で試すだけなら App Store の審査は要らない（Xcode から入れる）
- トレッドミルでカメラとセンサーを同時に使い、カメラの角度を答えにしてセンサーの角度を確かめる（下の「カメラに合わせる」）

## カメラに合わせる（`npm run compare:sensor`）

外ではカメラがないので、センサーだけの判定の線は、トレッドミルでカメラといっしょに走った記録で、カメラの骨格の判定に合うように決める。カメラ版は `?full=1`（全コマ記録）で走る。

- 使い方：`npm run compare:sensor -- <rfc-….json>`（ファイル名だけなら `RFC_RUNS_DIR` から読む）。`--win 秒`（まとめる窓、既定5秒）、`--json 出力.json`（決めた線と一致率。リポジトリの外に書く）
- 中身は `scripts/compare-sensor-camera.mjs`（計算は `scripts/sensor-camera.mjs`、テストは `scripts/sensor-camera.test.ts`）。ブロックの戻し方（`decodeBlock`）・カメラの線（`camera/params.ts` の `FORM`）・着地の山（`camera/landing.ts`）は src のものをそのまま使う
- 時刻：ブロックの t は届いた時刻で、Bluetooth の遅れがばらつく。センサーの時刻（ms）で並べ、前後15秒でいちばん遅れの少なかったブロックに合わせる
- 見る区間：カメラの段階が run で、歩数で走っていたコマ（5秒より短い区間は除く）。立った姿勢は、カメラが直立の基準を取った間（`phase:baseline` → `phase:run`）
- 出すもの：センサーごとの取れ方（切れ目・`sensor:` のできごと）、頭（頭の傾き と 首の角度・頭の位置・顎）、胸（胸の傾き と 上体）、ピッチ（足首の自己相関 と カメラ）、着地（足首の衝撃の山の左右差、カメラの着地の山との時刻・左右）、腕振り（手首のジャイロ と カメラの手首の振れ幅）
- 崩れの答えは、カメラの `FORM` の線で窓ごとに付け、センサーの傾きでいちばんよく分かれる線と一致率（見つけた割合・外れなかった割合・AUC）を出す。線の案は画面に出すだけで、`params.ts` には書かない（人が決める）。1本の走りの数十窓から出した数字なので、何本かで確かめてから入れる
- 立った姿勢は、アプリが覚えたとき（記録の `stand`、頭は `head.stand`）の直前3秒で取る（アプリと同じ）。`stand` がない記録だけ、カメラの直立の基準の間全部を使う（直立の前に体を動かしていると、向きがずれる）
- アプリの知らせ方そのもの（前の向き・基準の寄せ方・線・続ける長さ）は、`npm run replay:sensor -- <rfc-….json | Mac の記録のフォルダ> …` で記録を流し直して確かめる（`scripts/replay-sensor.mjs`）。知らせた回数・10分あたり・知らせたときのカメラの値・5秒の窓の一致率を出す。`--chest '{"follow":0}'` のように数字を上書きして試せる（`params.ts` は変えない）。Mac の記録（`hardware/sensor/records/…`）は区切りごとの回数を出す
- 真横から撮るので、奥の腕は骨格がほとんど取れない。腕振りは、見えるほうの手首で比べる（左右の腕は逆に同じ大きさで振る、とみなす）

## まだ決めていないこと

- 6個が本当に要るか。胸・腰・両足首の4個で足りるなら、そのほうが付けるのも買うのも楽
- 腰のセンサーを足すか（腰の落ち込みと上下動が測れるようになる）
- 各項目の線（どこから振動させるか）
- どの崩れをどの場所の振動で知らせるか（崩れた部位のノードを鳴らすか、いつも手首か）
- スマホに6個を BLE で同時につないで安定するか
