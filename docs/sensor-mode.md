# センサー版のしくみ（トレッドミルのカメラ版・腰スマホといっしょに使う形と、センサーだけで走る「センサーラン」）

体に付けたセンサーで走りを見て、崩れを**振動**で知らせて直す（声は補助。判断のしくみはカメラ版と共通）。トレッドミルのカメラ版が本線で、センサー版はその2本目の使い方。
誰のためか・振動に決めたわけは `docs/product.md`。コードは `src/modes/sensor/`（数字は `params.ts`）、機器は `hardware/sensor/`（`hardware/sensor/CLAUDE.md`）。

## カメラ版とセンサー版の得意な項目

声かけのしくみ（`src/core/engine.ts`）は共通にし、入り口と、見る項目の一覧だけを替える。

| 項目 | カメラ版 | センサー版 | センサーでの測り方 |
|---|---|---|---|
| 頭（頭が前に出る） | ◎ | ◎ | 頭のセンサー（おでこ）の前への傾き（いまある。下を向いたのとは分けられない） |
| 上体の前傾 | ◎ | ◎ | 胸のセンサーの前への傾き（いまあるのは猫背） |
| 体全体の前傾（足首→肩の線） | ◎ | ― | |
| 腰の落ち込み | ◎ | ― | 腰にセンサーがないので測らない |
| 腕振り | ― | ◎ | 手首のセンサーの前後の振れ幅 |
| 接地時間（接地が長い） | ― | ◎ | 両足首のジャイロで1歩ごとに着地・離地を見つけ、接地の割合を速さごとの市民ランナーの線と比べる（いまある） |
| 左右差 | ― | ◎ | 両足首の接地時間の左右差（いまある）。歩の間隔の左右差は、2つのセンサーの時計を合わせられないので見ない |
| 着地の衝撃 | ― | ○ | 足首のセンサーの、接地の瞬間の加速度（記録だけ。付け方で値が変わるので知らせない） |

## センサー

自作する（XIAO nRF52840 ＋ LSM6DSV16X、1個約3,250円）。構成・送る形・書き換え・作り方は `hardware/sensor/CLAUDE.md`。

- 付ける場所：いまは5か所。頭（おでこにヘッドバンド）、胸（心拍計の胸ベルト）、左手首（カメラから見える側）、左右の足首。右手首は空き。場所とセンサーの番号の対応は `params.ts` の `SLOTS` だけで決める（下の「カメラ版といっしょに使う」）
- 無線：BLE でスマホに直接送る。XIAO nRF52840 の技適（211-220207）の範囲で使う。SlimeVR の Smol Slime の独自無線（ESB）は技適の面でグレーなので使わない
- 送るもの：センサーごとに、時刻・ジャイロ・加速度を 100Hz（姿勢だけなら数十回/秒、着地の衝撃には数百回/秒要る）。向きはアプリの側で重力の向きから出す
- センサーどうしの時計は合わせていない（数 ms まで合わせる方法は未定。左右の歩の間隔を見ない理由は下の「接地時間と左右差」）

## 知らせ方：振動

崩れたら、その場所のノードを振動させる。いまの判断はスマホ（アプリ）の側にある。胸・頭は `lean.ts` が自分で知らせ、接地の項目は声かけのしくみ（`engine.ts` の `CueEngine`）の「いつ知らせるか・直ったらほめる・だんだん減らす」をそのまま使って、出口を声から振動に替えている。1時間の上限はどちらにも効く。
判断をどの層（センサーチップ・XIAO・スマホ）に置くか、モーター・部品・根拠は `hardware/sensor/docs/haptic.md`。

## 3つの走り方とセンサー

ホームのいちばん上で「トレッドミル／腰スマホ／センサーラン」を選び、「はじめる」1つで始める（選んだものは端末に覚える。`Home.tsx`）。
センサーを動かす役は3つで共通（`runner.ts` の `SensorRunner`。崩れの見分け・知らせ・記録は `session.ts` の `SensorSession`）で、違うのは「立った姿勢」と「走っている」をどこから取るかだけ。

| 走り方 | 立った姿勢・走っている | 知らせ | 記録 |
|---|---|---|---|
| トレッドミル（カメラ） | カメラの直立の基準（2つの立ち方）と、カメラの「走っている」 | 振動。接地の知らせは声でも | カメラ版の記録の `sensors`（`runs/camera/`） |
| 腰スマホ（テスト期間。センサーをつないでいるときだけ） | センサーで決める（下） | 振動だけ（スマホ版の声と重ねない） | スマホ版とは別の記録（`runs/sensor/rfc-sensor-…`、`with: 'phone'`。結果の `sensorLogId`）。時刻は `clock` で合わせる |
| センサーラン（`name.ts` の `SENSOR_RUN_NAME`） | センサーで決める（下） | 振動だけ。声は立つ・待つの案内と終わりの言葉 | `runs/sensor/rfc-sensor-…`（`runLog.ts`） |

### カメラなしで「立った姿勢」と「走っている」を決める（`gate.ts` の `MotionGate`、数字は `params.ts` の `RUN_GATE`・`STILL`）

- 立った姿勢（センサーラン）：2つの立ち方を声で案内する（下の「2つの立ち方」）。1つ目「いつもの楽な立ち方で、3秒止まってください」、2つ目「胸を開いて、肩を後ろに引いて、顎を軽く引いて、3秒止まってください」。案内を言い終えてから、胸と頭（つながっているもの）が3秒じっとしたら、その3秒の向きを測る（取れるまで20秒ごとに、いまの立ち方を言い直す）。決まったら「胸を開いた姿勢を登録しました。走り出すと始まります」。覚えるのは1回だけで、走り出したあとの信号待ちでは覚え直さない。胸も頭もなければ（足首だけ）、立つ案内は出さない
  - 腰スマホ（声の案内なし）は、今までどおり、胸と頭が3秒じっとしたら、その3秒を立った姿勢として覚える（猫背のまま立つと猫背を基準にしてしまう）
  - じっとしている：直近3秒、加速度のばらつき 0.03 g 以下・ジャイロの大きさの真ん中 15 dps 以下・上から1割 30 dps 以下。カメラが直立の基準を取った3秒（記録4本）は、胸 0.004〜0.026 g・真ん中 2〜9 dps・上から1割 4〜24 dps。頭を動かしていた2本（上から1割 88・127 dps）は、ここでは取り直しになる
- 走っている：直近3秒の加速度の大きさのばらつき（胸 0.4 g・頭 0.3 g・足首 0.6 g。胸 → 頭 → 足首の順に、つながっている最初の1つで見る）が3秒続けて線を越えたら走り出し、4秒続けて下なら止まった（信号・給水）。止まっている間は知らせず、基準も寄せず、接地は5秒止まるとためた1歩を捨てる（今までの「走っていない」と同じ）。体を曲げた見張り（bend）はそのまま
  - 線は、カメラといっしょに走った記録4本の3秒の窓で決めた。カメラが「走っている」とみた窓は胸 下から5%で 0.56〜0.65 g、頭 0.43〜0.51 g。走る前（ベルトの上の歩き・立つ）は胸 上から5%で 0.12〜0.24 g、頭 0.09〜0.23 g。足首は歩きと重なる（走り 下から5% 0.55〜0.74 g、走る前 上から5% 0.31〜0.65 g）ので、胸も頭もないときだけ使う
  - 同じ4本を流し直すと、カメラの「走っている」と1秒ごとに 93〜95% 合う（胸と頭がないと 80〜92%）。合わないのは、走り出し・止まりの3〜4秒の遅れと、カメラが一瞬「止まった」とみた秒（胸は走りの揺れのまま）。4本とも走る前に3秒じっとした間があり、立った姿勢を覚えられる
  - まだ確かめていない：外の歩き・坂・ゆっくりのジョグ（マラソンの後半）で線が合うか。記録の events の `sensor:run on/off <場所> <ばらつき>` と、1秒ごとのまとめ `sec` の `run` で確かめる

### 画面を消したとき（未確認）

- iPhone では、画面が消える（ロックされる）・ほかのアプリに切り替えると、ウェブのページの時計（setInterval）や Bluetooth の通知の受け取りが止まるおそれがある。Bluefy の振る舞いを書いた公式の文書は見つけられなかった（2026-11-05 に検索。iOS のアプリの中のブラウザ（WKWebView）は裏に回ると JavaScript が止まるという報告が Apple の開発者フォーラムにあるが、Bluefy で確かめたものではない）
- だから、センサーランと腰スマホは画面を消さずに使う：はじめるときに画面が消えない仕組み（Screen Wake Lock。`core/wake.ts`）を頼み、取れたかを画面に出す。取れないときは「自動ロック」を「なし」にしてもらう。画面の明るさを下げると電池がもつ。ポケットの中で触れて終わらないよう、センサーランの「終える」は長押し
- 止まったかは記録で分かる：アプリの時計が2秒より止まると events に `sensor:gap <秒>`、画面の見え方が変わると `sensor:visible hidden/visible`。センサーランの結果の画面にも「アプリが止まっていました」と出す

## カメラ版といっしょに使う（`src/modes/sensor/`）

トレッドミルのカメラ版で走りながら、自作のセンサーもつなげる。カメラの判定と声はそのままで、センサーは胸で猫背を、頭で頭が前に出たのを見てその場所を震わせ、値を記録に残す。
外ではカメラがないので、センサーの判定はセンサーだけで決める（カメラから受け取るのは、立った姿勢を取る時刻と「走っている」だけ）。カメラは、線を決めるための答えに使う。

- つなぎ方：ホームの「はじめる」の下の「センサーをつなぐ」で、場所ごとに「つなぐ」を押して選ぶ（Web Bluetooth。選ぶ画面はブラウザの決まりで押したときだけ）。「まとめてつなぐ」は、覚えている機器を選ばずにつなぎ、足りない分だけ選ぶ画面を続けて出す（続けて出せないブラウザは押し直しで次へ。起きたことは events の `sensor:ble …`）。一度選んだものは、`getDevices` があるブラウザなら次から押さずにつなぐ。押してつなげなかったときは押さずに3回（2秒おき）やり直し、使っている途中で切れたら、つながるまで3秒おきに押さずにつなぎ直す（`ble.ts`）。
  どのセンサーかは名前でなく、つないでから型番（0x2A24 の `RFC-IMU-番号`）で見分ける（無線で書き換えたあと、iPhone が「AdaDFU」の名前を覚えたままになるため。`hardware/sensor/CLAUDE.md`）。Bluefy が `getDevices` を持つか・選ぶ画面を続けて出せるかは未確認
- iPhone の Safari は Web Bluetooth がないので、つなげない（枠に Bluefy で開くよう出す）。センサーなしでも、カメラ版はそのまま使える
- 付ける場所とセンサーの対応は `params.ts` の `SLOTS` だけで決める（今は 頭=1、胸=2、左手首=4、左足首=6、右足首=3、右手首は空き。手首はカメラ（左から撮る）に見える左に付ける。5番はモーターが回らず外している。足首は 2026-11-05 から、左右の接地時間の差が体か付け方かを見るため 3番と6番を入れ替えて走っている。確かめたら 左足首=3・右足首=6 に戻す。受信画面 `viewer/viewer.html` と `tools/coach.py` は元の並びのまま）
- 崩れの見分け（`lean.ts` の `LeanDetector`、数字は `params.ts` の `HUNCH`（胸）と `HEAD`（頭）。胸と頭は同じしくみで、線だけ違う）：
  - 立った姿勢：2つの立ち方（下）のうち、胸を開いた立ち方の3秒の、そのセンサーの加速度の平均の向き。2つの差が小さかったときも、その3秒（今までの見方）
  - 走る前傾（今までの見方。2つの立ち方で見るときは、前の向きは2つの立ち方で決まり、走る前傾は差し引く上限つき。下）：カメラが歩数で「走っている」とみた時間で、走り出して10秒あとからの30秒。この間に立った姿勢から傾いた向きの平均を「前」とし、前への傾き（符号つき）の真ん中の値を走る前傾にする（胸はふつうの走りで 約12〜16°、頭は 約1〜15°）。横に傾いた・後ろに反ったのでは増えない。
    走る前傾が `fwdMin`（8°）より小さいときは「前」を決めず、向きによらない角度（立った姿勢からの傾きの大きさ）を使う。小さな傾きの向きは揺れで決まり、本当の前とずれる（2026-11-05：頭 2.9°・胸 6.1° で前の向きがほぼ横になり、頭が前に出ても数えず、カメラが「頭が前に出ています」と言った9回に頭は1回も震えなかった。向きによらない角度にすると11回震え、カメラの9回のうち5回に±15秒で合う）。
    その代わり、この形では後ろに反ったのも傾きに数える（頭は線が 前傾 + 18° なので、20° 上を向いたくらいでは鳴らない）。記録5本で、胸は 11-05、頭は 11-02 の2本・11-04・11-05 がこの形になる（`npm run replay:sensor`）
  - 基準：走る前傾から始め、線の下にいる間だけ時定数60秒で今の傾きへゆっくり寄せる。ベルトの上でセンサーが少しずつずれていくのを吸うため（2026-11-02 20:23 の走りで、胸の傾きが3分半で約15°増えたのに、カメラの上体は 2〜8° のまま。寄せないと2分すぎから胸が鳴り続けた）。線を越えている間は寄せないので、崩れたままなら知らせ続ける
  - 走っている間、前への傾きが基準 + margin を1.5秒続けて超えたら、その場所を1秒震わせ、超えたままなら4秒ごとに震わせ直す。線の下に戻れば止まる
  - margin：頭 18°。胸はランナーのレベルごと（`HUNCH_BY_LEVEL`：初心者 6°・中級 5.5°・上級 5°。レベルが分からなければ中級）。カメラが「背中が丸まっています」と言うときに胸も震えるよう、カメラの猫背の線（`STRICT` の hunch）に寄せた。
    2026-11-04 の走りで、前の 8° ではカメラの猫背の声3回（胸の値がある間）に1回しか震えず、5〜6° で2回。ふつうの区間の外れは10分あたり 1.4 → 2.2〜2.7回（`sim/result-chest-camera.md`、くわしくは `docs/validation-plan.md`）
  - 寄せることの代わり：ゆっくり進む崩れは吸ってしまう。胸で +12° の猫背なら約50秒、+15° なら約75秒、+20° なら約2分より時間をかけて進むと鳴らない（数秒〜数十秒で丸まるのは鳴る）
  - ずれの見張り（`slipSec`・`slipDecay`・`slipDrift`）：次のどちらかで、崩れではなくセンサーの付け位置がずれたとみなし、基準を直近10秒の傾きの真ん中の値へ置き直す。その場所を短く3回（0.3秒×3）震わせ、記録の events に `sensor:slip 胸 18.2→34.6`（ずれを測るもとの基準 → 置き直した基準）を残す。走っている間は画面を見られないので、走ったあとの結果の画面に「胸のセンサーが13分ごろにずれたようです。次は付け直してください」と出す（記録の `slips`・`head.slips` から、走り出してからの分。`slipText.ts`・`SlipNote.tsx`）。声は出さない
    - 線を越えていた時間（線の下にいる間は同じ速さで減らす）が75秒に達した：急にずれて、線を越えたままになったとき。寄せる基準は線の下でしか動かないので、これがないと走り終わるまで4秒ごとに鳴る
    - 寄せた基準が、走る前傾（前にずれとみなしたときは、そのときの基準）から前へ 胸 8°・頭 15° 動いた：少しずつずれたとき（寄せて吸っているので知らせる回数は変わらないが、付け直しを促す）。後ろへ動いたのは見ない（鳴りにくくなるだけ）
    - （カメラ版・胸だけ）線を越えて10秒たっても、カメラの上体の前傾が 1.5°、頭の位置（肩→耳）が 2° も、線の下にいた直近60秒より増えていない（`camSlipSec`・`camRise`・`camHeadRise`）：カメラは崩れていないと見ているので、ずれとみなす。カメラは走っている間コマを間引くので、両方にカメラの値が2秒ぶん（tick 20回）ないうちは決めず、75秒を待つ。
      2026-11-05 に胸のバンドが回った2回は、カメラの値が変わらなかった（2172秒：その前後で上体 5.2 → 5.0°・頭の位置 38 → 38°、2396秒：上体 5.4 → 4.6°・頭の位置 39 → 38°）。前は1回目のあと 2280〜2351秒に約72秒鳴り続けた（この回は、上の向きによらない角度にしたことで鳴らなくなった。回ったのがおもに横向きだったため）。いまは 2396秒のずれで4回鳴って 2412秒に置き直す（カメラなしなら 2471秒）。
      11-03 の 305〜343秒（胸が基準 +12〜17°、上体は +0.9° だけ、頭の位置は +5.6°）は頭の位置が増えているので置き直さない（上体だけを見ると置き直した。背中を丸めると上体の線はあまり動かず、頭が落ちる）。決めたもとは2つの出来事だけなので、線はまだ仮
    - 急に大きく回ったことだけでは、ずれと分けられない：3秒で 20° を越えて回るのは、ふつうの走りの間にも 11-03・11-04・11-05 で何度もあり（11-03 のわざとの猫背で 33°）、11-05 のずれ（21°）と同じ大きさだった
    - 仮想実験（`sim/lean-slip.sim.ts`、結果は `sim/result-lean-slip.md`。揺れは 2026-11-03 15:08 の胸に合わせた）：胸 +13° のわざとの猫背 40秒・60秒・60秒×2（間60秒）は、20通りのどれもずれとみなさず、見張りなしと同じ回数（60秒で約15回。3つのレベルとも）知らせる。急に +13° ずれると、見張りなしで約136回のところ約19回（約75秒）で黙る。上級（5°）は、+13° を5分かけてゆっくりずれると、ずれとみなす（約510秒）までに約16回鳴る（初心者 6° では0回）。頭は線が広く、+22° のずれでも線のすぐ上を出入りするだけで、もともと鳴り続けはしない
    - 見張りの代わり：75秒より長く崩れたままだと、ずれとみなして黙り、基準が崩れた形に寄る（胸で 90秒の猫背なら20通りのうち19回）。戻ったあと基準が下がるまでの1〜2分は、鳴りにくい
    - 走り出してすぐの短いずれ（15:08 の 225〜240秒、+9° が10秒ほど。そのあと +3〜4° 上で落ち着いた）は、短い猫背と分けられないので鳴る
  - 頭のセンサーは、首が前に出たのと下を向いた（うなずいた）のを同じに見る（カメラの顎の角度と r −0.97）
  - 猫背を頭より先に（2026-11-06 本人の決め。カメラ版と同じ考え。`params.ts` の `HEAD_YIELD`、`lean.ts` の `HeadYield`）：胸と頭は別々に震えるが、胸が線を越えている間は頭を震わせない（胸が知らせる）。
    胸が上がってきている（直近6秒に胸の線を越えた tick がある、または平均が 基準 + 0.6 × 線の幅 以上）ときも、頭の知らせを4秒まで待たせる。待つ間に胸が震えればそれで済ませ、
    待ち終わりに胸がまだ越えている・上がってきていれば頭の代わりに胸を震わせ（胸の次の知らせまでの間は見ない。胸が1時間の上限なら頭）、そうでなければ頭を震わせる（頭が線の下に戻っていても）。
    胸に替えたら、頭も知らせたものとして頭の次の知らせまでの間を数え直す。替えたときは events に `sensor:yield 頭→胸`（待ったあと頭なら `sensor:yield 頭`）

## 2つの立ち方（カメラ版とセンサーラン。`lean.ts` の `setPoses`、`session.ts` の `pose`・`calibrate`、数字は `params.ts` の `POSE` と `LeanParams` の `pose…`。どれも仮の値）

なぜ：カメラの立ち姿勢の線（腰→肩・肩→耳）では、本人のいつもの猫背（背中が丸く、肩が前）とまっすぐを分けられなかった（記録と研究データ Riglet 2024 の両方で）。それなのに「頭も背中もまっすぐです」と言っていた。
また、今までの胸の見方は「立った姿勢 → 走り出し30秒の前傾」からの増えで見るので、猫背のまま走り出すと猫背を基準にして知らせなかった（本人の課題はまさにこれで、ランナー塾のコーチの指摘）。
胸のセンサーは付けるたびに角度が変わるので、立った姿勢の傾きそのものに決まった線は持てない。そこで、その日のうちの2つの立ち方で、猫背の向きと基準（b）を決め、そこからの決まった度数を線にする。

- 測り方：案内の声を言い終えてから、a「いつもの楽な立ち方」と b「胸を開いて、肩を後ろに引いて、顎を軽く引いた立ち方」を3秒ずつ。カメラ版は、カメラの頭の位置と上体も両方で残す（`pose:a`・`pose:b` のできごと）
- 物差し：胸（頭）のセンサーの重力の向きの、b から a への回り方を「前（猫背の向き）」、その角度（a と b の差）を猫背の大きさにする。走り出しの前傾から前の向きを決めるのはやめる（前傾が小さいと向きが揺れで決まり、11-05 は横向きになった）。猫背の割合 ＝ b からその向きに沿った傾き ÷ 差（b ＝ 0、a ＝ 1。記録の 1秒ごとのまとめ `sec` の `chestIdx`・`headIdx`）
- 差が小さい：胸（なければ頭）で `poseMin`（胸 5°・頭 8°）より小さければ、「2つの姿勢の違いが小さく、うまく測れませんでした。もう一度お願いします」と言って a から測り直す（`POSE.retries` 2回まで）。それでも小さければ「姿勢の違いが小さいので、今日はこの姿勢で始めます」と言い、b を立った姿勢にして今までの見方にする（fallback）。頭は、頭の差だけが小さければ頭だけ今までの見方（頭の margin のまま）。
  `poseMin` は姿勢を本当に変えたかを見るだけの値：記録5本の立った3秒の中で、1秒ずつの胸の向きは3秒の平均から 0.8〜3.1°、頭は 0.9〜10.5° 動いた
- 走ると体ごと足首から前に傾き、それも同じ向き（前）に出る。分けられないので、走り出し30秒の前傾（b から前の向きに沿って）を基準として差し引くが、`poseCap`（10°）までにする。猫背のまま走り出すと、差し引けない分が線を越えて知らせる。
  カメラ版は、カメラの上体の前傾の増え（b の立ち姿勢から、同じ30秒の真ん中）+ `poseCamSlack`（5°）までにも抑える（カメラの上体には猫背がほとんど映らず、おもに体ごとの前傾が映るため）。どれで抑えたかを記録の `runLean.by`（sensor・cap・camera）に残す。
  記録5本で、カメラの上体の前傾は 立つ → 走る で +8.1〜+10.9°、胸の走る前傾は 6.3〜22.6°（付け方のずれ・猫背も入る）
- 線（胸）：基準 + `poseLine` 5°（b→a の向きに沿って。どのレベルも同じ。2026-11-06 本人の決め「比率じゃなくて絶対値で…5度」。仮の値）。a と b の差は、向きと基準を決めるのに使い、線の幅には使わない。1.5秒続いたら震わせるなど、ほかは今までと同じ。
  前は 基準 + max(margin, `poseFrac` × 差)（`poseFrac` 初心者 0.6・中級 0.5・上級 0.4。margin 5〜6° より狭くしない）で、胸をよく開ける人ほど線が遠くなった（差 25° で上級 10°）。わざと短く背中を丸めても胸は +4〜6° しか動かず、届かなかった。
  2つの立ち方で見られないとき（fallback・今までの見方）の線は、今までどおりレベルごとの margin（初心者 6°・中級 5.5°・上級 5°）。
  頭は割合のまま（`poseLine` 0）：下の「頭：最初から前に出たまま走り出す」の決まり（線の幅 max(8°, 0.5 × 差)・3秒・走り出し5秒から・ほめる）
- ふつうの走りでの 5° の線（確かめたのは今までの見方の記録だけ。2つの立ち方の記録はまだない）：11-05 の1秒ごとの胸（`sec` の chest − chestRef）は 標準偏差 5.0°・下から5% −4.8°・上から5% +7.5°（このときの胸は前の向きが決まらず、向きによらない角度）。
  走っていた秒のうち +5° を越えた秒は 9.6%（+5.5° で 8.3%）、2秒続けて越えたのは 10分あたり 2.4回（+5.5° で 1.0回）。

  11-02 20:23（4分、センサーがずれた走り）15.0 → 49.8回、11-02 18:43 は胸の基準ができず 0回。11-04・11-05 の知らせは、どれもカメラの答えが「崩れでない」とき
- 線の幅と、ほかの決まりの関わり：
  - `poseCap` 10°・`poseCamSlack` 5°（差し引く走る前傾の上限）は変えない。線はその基準からの 5°。体ごとの前傾が 10°（カメラ版はカメラの上体の増え + 5°）より大きい人は、その分だけ線に近くなる
  - ずれと猫背の見分け（下）の下の端は、`poseIdxMin` × 差 と 線の幅 の小さいほうにした。割合だけ（0.4 × 差）だと、差 25° の人は線（5°）を越えても 10° までは「猫背としてありうる」に入らず、猫背のまま約75秒でずれとみなして黙ってしまうため
  - 頭の知らせを待たせる「胸が上がってきている」（`HEAD_YIELD.riseFrac` 0.6 × 線の幅）は、線が 5° なら 基準 + 3°。差の大きい人では前より低くなり、頭を待たせる秒が増えるかもしれない（記録で確かめていない）
- 知らせられる範囲：猫背のまま走り出したときは、差 + 体ごとの前傾 > min(差 + 体ごと, 10) + 5 のときだけ知らせる。例：差 15°・体ごと 8° → 23 > 15 で知らせる。差 8°・体ごと 4° → 12 < 15 で知らせない（12° のうち 10° を走る前傾として差し引き、猫背の分の大半が基準に入る）。
  体ごとの前傾が 10 + 5 = 15° より大きいと、胸を開いていても鳴る（`sim/pose.sim.ts`、結果は `sim/result-pose.md`。体ごと 12° の「胸を開いたまま」は 10通りで 0回（0〜6回））
- ずれと猫背の見分け（2つの立ち方で見るときだけ。今までの見方は変えない）：線を越えている向きが猫背としてありうる間は、ずれの見張り（`slipSec`）に数えず、基準を前へ寄せず（`follow`）、寄せた基準が動いた（`slipDrift`）ともみなさない。
  ありうる：直近10秒の真ん中の値で、b→a に沿った傾き（差し引いた走る前傾を除く）が min(`poseIdxMin` 0.4 × 差, 線の幅 5°)〜`poseSlipIdx` 1.8 × 差、b→a と直角な横の傾きが max(`poseSlipSide` 8°, `poseSlipSideFrac` 0.6 × 差) 以下。
  ベルトが横に回った・割合が 1.8 より大きいときは、今までどおり約75秒でずれとみなす。カメラ版のカメラとの食い違い（`camSlipSec`）は今までどおり。b→a に沿ってずれたセンサーは猫背と見分けられない（センサーランでは鳴り続ける。カメラ版はカメラで見分ける）。
  猫背のまま走り続けるときの知らせ直し：続けて `poseBackoffAfter` 5回（4秒ごと、約20秒）知らせたら `poseBackoffEvery` 15秒ごと。線の下に `poseBackoffReset` 10秒いたら4秒ごとに戻す。どれも仮の値。
  仮想実験（`sim/result-pose.md`）で、猫背のまま10分走ると、差 10° 以上・体ごと 8° 以上で知らせ続け（1時間の上限 `LIMIT.perHour` の 20回に届く）、ずれとはみなさない。`sensor:slip` には、置き直した基準の猫背の割合（`idx`）も残す
- カメラ版：カメラの直立の基準も b で取り、カメラの立ち姿勢の線は b でも越えていたら知らせるだけ（`docs/camera-mode.md` の「走りの流れ」の2）
- 記録：胸はいちばん上の `pose`、頭は `head.pose`（a・b の向き、差、`mode`（pose・fallback）、測った回数 `tries`、回ごとの差 `degs`、線の幅 `margin`（胸は決まった度数 `line`、頭は割合 `frac` も）、カメラ版は a・b のカメラの上体と頭の位置 `cam`）。走る前傾 `runLean` には差し引いた分 `offset`・`by`・`cam`。events には `sensor:pose a 胸・頭 cam …`・`sensor:poseDiff 胸 12.3 頭 8.1 try 1`・`sensor:pose 胸 pose 12.3 margin 6.2` か `sensor:poseFallback 胸 3.1`・`sensor:runLean 18.2 offset 10.0 cap`

### 頭：最初から前に出たまま走り出す（`params.ts` の `HEAD` の `poseCap`・`poseMargin`・`poseHold`・`poseStart`・`posePraise`・`poseBackoff…`）

本人は走り出しから頭が前に出ている（カメラの記録で、走り出しの首 31〜41°。カメラの「良い例」は 22〜31°）。今までの頭の見方は走り出しの頭を基準にするので、それを知らせなかった。
2つの立ち方で頭の差が `poseMin`（8°）以上あれば、b（顎を引いた頭）を目指す形として、走り出しから知らせる。知らせは振動だけ（カメラ版は、カメラが頭の声を言うので重ねない。胸も同じ。センサーで声も出すのは接地の項目だけ）。

- 付け方：頭のセンサーは、おでこにヘッドバンドで付ける（頭のてっぺんはセンサーの後ろ）。頭は固いので、どこにどの向きで付けても頭の回り方は同じに見える（前の向きは b→a で決め、軸を決め打ちしない）。
  ヘッドバンドが汗でずれて上下に回ると、b→a に沿ってずれたのと見分けられない（センサーランでは鳴り続ける）
- 走り出し：走って `poseStart` 5秒から、走る前傾を覚え終わる（40秒）のを待たずに、基準を `poseCap` 3° として見る。線の上に `poseHold` 3秒続いたら頭を震わせる（前に出たまま走り出すと約8秒）。
  覚え終わったら、基準は 走り出しの頭の前傾（b から）と 3° の小さいほう。直した頭（b に近い頭）が基準になり、いつもの頭へゆっくり戻っても基準は前へ寄せない（猫背の割合 0.4 以上の間）ので、また知らせる
- 差し引く走る前傾は 3°（胸は10°）：走ると体ごと前に傾くが、頭はほとんど回らない（目線を保つ）。記録5本で、立った姿勢 → 走り出しで カメラの上体は +7.3〜+10.6° 増えたのに、頭のセンサーの回り方は 1.8・6.7・11.0・6.9・3.3°（どの日も、いつもの前に出た頭で走っている）。
  2本は体ごとの前傾より小さく、体ごとの分が頭に出るのは多くても約2〜3°。走り出しの胸の前傾（6〜23°）を体ごとの分にするのは、頭には大きすぎる（日ごとの頭の回り方と、カメラの上体・首・顎の増えの相関は 5本で −0.1〜0.14。付け方が日ごとに違い、比べられない）
- 線の幅：max(`poseMargin` 8°, 0.5 × 差)。今までの頭の 18°（カメラの「頭が大きく前」に合わせた線）では、差が 36° より小さいと、いつもの頭では鳴らない。
  胸と違い、割合のまま（`poseLine` 0。2026-11-06 の胸の決めでは頭は変えていない）：差 16° までは線は 8° で決まり、それより大きいと差とともに遠くなる（差 25° で 12.5°）。差し引く走る前傾は `poseCap` 3° まで。頭の a と b の差は、まだ記録で測っていない
  8° と3秒は、記録5本を流して決めた：走っている頭の揺れ（下を向く・見回す）での知らせ（カメラが首 40° 未満のとき）は、ふつうの走り（11-04・11-05）で 10分あたり 線 8°・1.5秒 4.8/3.7 回 → 8°・3秒 1.3/0.7 回
- 知らせ直す間隔：続けて3回（4秒ごと）のあとは30秒ごと（胸は5回のあと15秒ごと）。いつもの頭はずっと続く癖で、4秒ごとにおでこを震わせ続けるとうるさく（骨に響く）、うなずきと前に出たのを分けられない分、外れの知らせもあるため。線の下に10秒いたら数え直す
- 直ったら：知らせたあと線の下に `posePraise` 3秒いたら、頭を短く2回（0.15秒）震わせる（`sensor:headOk`）。声は出さない（カメラ版はカメラが頭の声を言うので、重ねない）。
  ほかの声を話している・待っている間は言わない（カメラの頭の声と重なりうるので、カメラ版の頭の声とどちらを使うかは、まだ決めていない）
- 見えるもの・見えないもの：センサーは重力の向きしか見ないので、見えるのは頭の回り方（うなずき・上を向く）だけ。頭が前へずれる（あごを突き出す。首の下は前に倒れ、首の上は反る）のは、回り方が変わらなければ見えない（あごを突き出すと、頭はむしろ上を向くこともある）。
  加速度から位置を出すのは、積み重ねのずれで使えない。胸と頭の差（首の回り方）も回り方なので、ずれは見えない。記録の走り出しでは、カメラの頭の位置（肩→耳）は 立つ → 走る で +16〜+26° 増えたが、顎の角度（耳→鼻）は −4〜−12°、頭のセンサーは 2〜11° しか回っていない。
  そのため、いつもの頭が「回り方」として a と b で違うときだけ効く。a と b の頭の差が 8° より小さければ、頭は今までの見方（走り出しを基準に 18°）のまま
- 胸と頭の差は知らせには使わない（胸の猫背が入り、目線を保つための首の反りも入るので、目指す形がないと読めない）。1秒ごとのまとめ `sec` の `chestIdx`・`headIdx` に両方残るので、あとで比べられる
- 流し直し（b を記録の立った姿勢、a をそこから走り出しの頭の向きへ 10° とした仮のもの。2つの立ち方の記録はまだない）：11-03（走り出しの頭 12.3°）は走って8秒で知らせ始め（今までの値なら163秒）、ほかの4本（走り出しの頭 1〜7°）は走り出しでは鳴らない。
  5本で知らせ 48回・ほめた 32回、首 30° 未満のときの知らせ 2回。`npm run replay:sensor` は、記録に頭の `pose` があれば、覚え終わる前に知らせた回数とほめた回数も出す

## 接地時間と左右差（足首の2つ。`contact.ts`・`contactCoach.ts`、数字は `params.ts` の `STEP`・`CONTACT`）

- 見つけ方（`StepDetector`）：足首（すね）のジャイロの、前後の面の回転の速さを使う。振り出しの大きな山のあと、0 を下へ切ってから 26ms で着地。次の振り出しの前に 0 を上へ切る、その前 0.25秒の谷から 90ms 前が離地。軸はジャイロの主成分（付け方の向きは決めない）、符号は両方の向きで1歩を探して、もっともらしい1歩が多いほう。時刻はセンサーの時計で数える（Bluetooth の遅れが入らない）
  - ずらす量は RBDS（Fukuchi 2017、床反力つき。読めた22人）の印から作ったすねの角速度で決めた。同じデータで、接地時間のずれは1歩ずつ ±18〜21ms、人・足ごとの真ん中の値で 2 ± 17ms、取りこぼし 0〜1%（100Hz と、記録の 50Hz でほぼ同じ。`sim/result-contact.md`）。印から作った値なので皮膚や衝撃の揺れは入らず、実機の足首のセンサーを床反力と比べた答えは、まだない
- 接地が長い（腰が落ちている）：線は今日の走り出しではなく、研究データの市民ランナー。接地の割合（接地時間 ÷ 1歩き）は速さで変わるので、すねの振れ幅 ÷ 1歩きの時間から速さを見積もり、その速さの平均 + 2 × 標準偏差（Patoz ら 2022、115人：時速9km 37.7 ± 3.1%、11km 34.7 ± 2.5%、13km 32.6 ± 2.2%。表の外は端の値）を越えたら知らせる。RBDS の22人は、床反力の本当の値で誰も越えない
  - 接地の割合が高い人は、接地の間に脚を深く曲げる（Patoz ら 2020）。ただ、接地が長いのは腰が落ちたときだけではない（大また・かかとからの着地でも長くなる。11-03 の「足を前に出す」1分で、接地の割合は z 2.1 まで上がった）。高い接地の割合はそういう走り方の型でもあり、効率は変わらないという研究もある（Lussiana ら 2019）ので、線は外れた人だけに当たる高さにした
- 左右差：接地時間の |右 − 左| ÷ 平均 が 15% を越えたら、長いほうの足首を震わせる（20秒の窓）。RBDS の床反力では、どの人も 10% 未満（いちばん大きくて 9.3%）、Garmin の「左右のバランス」でも 52.2% を越える（左右差 約9%）のは上から5%。付け方が左右で違うと接地時間にも見かけの差が出るので、振り出しの山が左右で 1.25 倍より違えば左右差は見ない
  - 着地の衝撃の左右差は記録だけ（付け方・50Hz の間引きで値が大きく変わる。4本とも右が 1〜3割重かったが、本当の差か付け方かは分けられない）。歩の間隔（左 → 右と右 → 左）の左右差は、2つのセンサーの時計の差を数 ms まで合わせられない（10ms ずれると見かけで約5%）ので見ない
- 知らせ方：声かけのしくみ（`engine.ts` の `CueEngine`）をそのまま使う（6秒の平均が線を越えたら知らせ、同じ項目は30秒あけ、直ったらほめ、だんだん減らす、1時間の上限）。接地が長いのは両足首、左右差は長いほうの足首を1秒震わせ、直ったら同じ場所を短く2回。カメラ版で走っている間は声も出す（「接地が長くなっています。ピッチを少し上げて、軽く。」、「右足の接地が長くなっています…」、直ったら「いい感じです」「左右がそろいました」）。カメラの声と重ならないよう、声が出ている間は振動だけ
  - 言葉は起きていること（接地が長い）だけを言い、「腰が落ちています」とは言わない：接地は腰が落ちたときだけでなく、大また・かかとからの着地でも長くなる（上）。直し方は体の外に意識を向ける「ピッチを少し上げて」（カメラの腰の高さ `cueHip` は腰そのものを測っているので、そのまま）。頭の声も同じ考えで「頭が前に出ています。目線を少し先に。」（顎を引く指示は、止まって形を作る2つの立ち方の案内だけ）
- 知らせない間：走り出して30秒・見積もった速さが20秒の間に1割より変わった・ピッチが1割より変わった間は、腰と左右差を知らせない（線より下の値は渡すので、直ったかは見る。同じ速さで大またにすると接地の割合が上がり、腰と取り違えるため）。オーバーストライドは速さだけを見る。歩き（接地の割合 > 0.5）の1歩は捨てる
- オーバーストライド（足が体より前に着く。`CONTACT` の `refSec`・`sameV`・`overDrop`・`overHold`）：ベルトの速さが同じなのに大またにすると、ピッチが落ち、接地がのびる。走り出し（30秒のあと、速さが落ち着いてから60秒）のピッチと接地時間の真ん中をその速さの基準にし、見積もった速さが基準の ±8% の内にある間、ピッチが 6% より落ちたまま20秒続いたら、両足首を1秒震わせる（声はカメラの着地と同じ「足が体より前に着いています。歩幅を少し小さくして、体の真下に足を下ろしてください。」）。戻ったら同じ場所を短く2回とほめる声。速さが60秒より長く違ったら、新しい速さで基準を覚え直す。
  - 着地を変えると負担がふくらはぎ・アキレス腱に移るので、変えるのは少しずつ、週単位で（結果の画面にも同じ一文を出す）。
  - 一瞬わざと崩したのは知らせない（本人と決めた）。2026-11-05 のわざと大またの約15秒（ピッチ 170 → 146〜153、接地 255 → 336ms、見積もった速さは 7.7〜8.2 km/h で変わらず）は、20秒続かないので知らせない。記録5本のふつうの走りでは、20秒続いた落ち方はいちばん大きくて 2.1%（線 6%）。続けて大またにした記録はまだないので、知らせることは作りものの値（テスト）でしか確かめていない
  - 線のもと：ピッチを 5〜10% 上げると足が体の近くに着き、ひざと股関節の負担が減る（Heiderscheit 2011）。その逆向きを見る。自分の記録では、同じ速さのふつうのピッチの揺れは ±2.5%
  - すねの角度（着地のときのすねの前傾）でも見られるが、足首のジャイロから着地の瞬間の角度を出す確かめがまだないので使っていない
- 記録：camera の記録の events に `sensor:contact sit 2.1`（知らせた。値は平均から標準偏差いくつぶん上か、左右差なら %、オーバーストライド `stride` ならピッチの落ち方 %）、`sensor:contactOk`（ほめた）、30秒ごとの `sensor:steps df … ct … L … R … v … cad … imp … drop …`（drop：走り出しからのピッチの落ち方 %）
- 自分の記録（`sim/result-contact.md` の③）：接地時間は 264〜295ms、接地の割合 0.37〜0.39（時速9km の市民ランナーの平均くらい）。4本・判定した54分で知らせは2回（10分あたり 0.4回。どちらも 11-04）：1486秒の左右差（左が 17% 長い。この走りは左が 8% 長いのがふつうで、ほかの3本は左右差 2% 以内）と、2240秒の腰（カメラが「足が体より前に着いています」と言ったあとで、ピッチが 164 → 147 に落ちた区間）
- 速さの見積もり（`contact.ts`、数字は `STEP`）：速さ（m/s）＝ `speedA` ＋ `speedB` × すねの振れ幅 ÷ 1歩きの時間。RBDS の 54本で r 0.91、人によるばらつき ±0.30 m/s（RBDS の式のままなら ±1.1 km/h）。
  切片 `speedA` の既定は RBDS の当てはめの −0.183 で、人ごとに合わせる（`speedFit.ts`）：トレッドミルのカメラ版でベルトの速さを入れた走りが終わるごとに、1歩ごとの「ベルトの速さ − speedB × 振れ幅 ÷ 1歩き」の中央値（両足あわせて100歩以上ある走りだけ）を端末に残し、直近5回の中央値を使う（RBDS の値から ±0.6 m/s より離れたものは入れ間違いとして使わない）。ベルトの速さを入れない走り・新しい端末では RBDS の値のまま。記録の events に `speedFit:A …`。
  人ごとに合わせるのは、自分の 2026-11-05 の走り（トレッドミル 時速9.0km で30分）が RBDS の式では 8.1 km/h（5〜95%：7.9〜8.3）と低く出たため。この走りに手で合わせた切片 +0.09（+0.27 m/s ＝ RBDS の人によるばらつきの 0.9倍）なら 9.0（8.7〜9.1）、11-04（本人の平均で 約7 km/h）は 5.8（5.7〜6.4）→ 6.8（6.7〜7.4）。人ごとの合わせ方に通した結果は `docs/validation-plan.md` の「速さごとのよい例」。
  外（センサーラン）は、人ごとに合わせた式でそのまま見積もる。GPS の速さ（`runner.ts` の `onGps`）を合わせに使う口はあるが、GPS の速さの精度を記録で確かめるまでつないでいない。
  速さは接地の割合の線（時速9km より遅いと端の値）と、オーバーストライドの「同じ速さ」の見分けに使う
- まだ確かめていないこと：わざと腰を落とした走りで知らせるか（記録がない）、続けて大またにした走りで知らせるか（記録がない）、足首の振動を走りながら感じ取れるか、速さの見積もりが時速9km 以外でベルトの速さと合うか

## 長い走りでの知らせの上限（`core/params.ts` の `LIMIT.perHour`）

外のセンサーランはマラソンで7時間まで。崩れたまま走り続けると、胸は4秒 → 15秒ごとで1時間に約240回、接地は30秒ごとで約120回震えていた。決まりは1つだけ：

- 走った時間を1時間ずつの枠に切り、同じ項目の知らせが枠の中で 20 回に達したら、その枠の残りはその項目を知らせない。次の枠で数え直す。知らせない間も測って記録する
- 胸・頭（`lean.ts`）と、接地のしくみ（`engine.ts` の `CueEngine`。カメラ版・スマホ版の項目にも同じ決まりが効く）で同じ数字。カメラの正しいフォームの線の声（見る役が自分で決める声）も、上限に達した項目は出ない（`since(項目)` が 0 になる）
- 記録：events に `sensor:capped 胸`・`sensor:capped sit`（上限に達した知らせ）、`summary.capped` に項目ごとの回数。結果の画面にも「その項目はその1時間の残りは知らせていません」と出す
- 20 は仮の値（根拠なし）。知らせの間隔から：胸は2つの立ち方で見るときは約4分（4秒 ×5回 → 15秒ごと）、1つの立ち方のとき（腰スマホ・差が小さかった日）は約80秒の猫背で達し、そのあと1時間近く震えない。実機の記録（`summary.cues`・`capped`）を見て決め直す。知らせをだんだん減らす決まりはまだ作らない（回数を数えるだけ）

## 位置情報（GPS）の記録（センサーランだけ。`gps.ts`、数字は `params.ts` の `GPS`）

上りでは体ごと前に傾き、接地も長くなるので、坂で知らせを変えるかをあとで決めたい。そのために GPS の速さと高さを記録に残すだけで、知らせには使わない。

- センサーランを始めると `navigator.geolocation.watchPosition` で位置を受け取り、1秒ごとのまとめ `sec` に `gpsV`（速さ km/h。端末が出した速さ）・`gpsAcc`（横の誤差 m）・`alt`（高さ m）・`altAcc`（高さの誤差 m）を入れる（最後の位置が10秒より古ければ null）。緯度・経度は残さない（家の場所が分かるため）。走り終わったら止める（電池）
- 電池のため、ふつうの精度（`enableHighAccuracy: false`）で頼む。ふつうの精度では高さが付かないことがある（iPhone は Wi-Fi で決めた位置に高さを付けない）ので、記録の `alt` がいつも null なら `GPS.highAccuracy` を true にして確かめる
- 様子は events に `gps: on`（最初の位置が来た）・`gps: none`（位置情報のないブラウザ）・`gps: denied`（許可されていない）・`gps: error <code>`（取れない 2・時間切れ 3）、`summary.gps` にも残す。走っている画面のチップにも出す
- 未確認：Bluefy で位置情報が取れるか（取れなければ `gps: none` か `denied` が残り、坂はこの記録では見られない）。速さの見積もり（`v`）を GPS に合わせる口は `SensorRunner` の `onGps`（位置が届くたびに呼ぶ。いまは何もつないでいない）
- カメラ版（トレッドミル）と腰スマホでは受け取らない（腰スマホはスマホ版が自分で受け取る）

## カメラに合わせる（`npm run compare:sensor`）

外ではカメラがないので、センサーだけの判定の線は、トレッドミルでカメラといっしょに走った記録で、カメラの骨格の判定に合うように決める。カメラ版は `?full=1`（全コマ記録）で走る。

- 使い方：`npm run compare:sensor -- <rfc-….json>`（ファイル名だけなら `RFC_RUNS_DIR` から読む）。`--win 秒`（まとめる窓、既定5秒）、`--json 出力.json`（決めた線と一致率。リポジトリの外に書く）
- 中身は `scripts/compare-sensor-camera.mjs`（計算は `scripts/sensor-camera.mjs`、テストは `scripts/sensor-camera.test.ts`）。ブロックの戻し方（`decodeBlock`）・カメラの線（`camera/params.ts` の `FORM`）・着地の山（`camera/landing.ts`）は src のものをそのまま使う
- 時刻：ブロックの t は届いた時刻で、Bluetooth の遅れがばらつく。センサーの時刻（ms）で並べ、前後15秒でいちばん遅れの少なかったブロックに合わせる
- 見る区間：カメラの段階が run で、歩数で走っていたコマ（5秒より短い区間は除く）。立った姿勢は、カメラが直立の基準を取った間（`phase:baseline` → `phase:run`）
- 出すもの：センサーごとの取れ方（切れ目・`sensor:` のできごと）、頭（頭の傾き と 首の角度・頭の位置・顎）、胸（胸の傾き と 上体）、ピッチ（足首の自己相関 と カメラ）、着地（足首の衝撃の山の左右差、カメラの着地の山との時刻・左右）、腕振り（手首のジャイロ と カメラの手首の振れ幅）
- 崩れの答えは、カメラの `FORM` の線で窓ごとに付け、センサーの傾きでいちばんよく分かれる線と一致率（見つけた割合・外れなかった割合・AUC）を出す。線の案は画面に出すだけで、`params.ts` には書かない（人が決める）。1本の走りの数十窓から出した数字なので、何本かで確かめてから入れる
- 立った姿勢は、アプリが覚えたとき（記録の `stand`、頭は `head.stand`）の直前3秒で取る（アプリと同じ）。`stand` がない記録だけ、カメラの直立の基準の間全部を使う（直立の前に体を動かしていると、向きがずれる）
- アプリの知らせ方そのもの（前の向き・基準の寄せ方・線・続ける長さ）は、`npm run replay:sensor -- <rfc-….json | Mac の記録のフォルダ> …` で記録を流し直して確かめる（`scripts/replay-sensor.mjs`）。知らせた回数・10分あたり・知らせたときのカメラの値・ずれとみなした時刻・5秒の窓の一致率を出す。走っているかは、カメラの行のいちばん近い前の行で決める。カメラは走っている間、骨格を間引いて取る（行のない間が7〜17秒）が、アプリはその間も前の判定のまま「走っている」とするので、20秒までの行のない間は前の行のままにする（そうしないと、間引いている間は走っていないことになり、基準が寄らず、知らせた回数がアプリの記録と合わない）。`--chest '{"follow":0}'` のように数字を上書きして試せる（`params.ts` は変えない）。Mac の記録（`hardware/sensor/records/…`）は区切りごとの回数を出す
- 真横から撮るので、奥の腕は骨格がほとんど取れない。腕振りは、見えるほうの手首で比べる（左右の腕は逆に同じ大きさで振る、とみなす）
